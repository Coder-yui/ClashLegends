# 新卡与素材接入清单

完整新卡按 **战斗逻辑 → 模型动画 → 卡面 → 音频 → 联合验收** 推进。只替换某类素材时执行对应阶段，不顺带改变玩法。

## 开始前

1. 检查现有修改，确定卡牌身份、费用、定位、主动候选和可复用机制。
2. 确定稳定英文标识，建立 [单位总览](units/README.md)，使用 [模板](templates/card.md)。
3. 确认素材来源和依赖；待开发队列必须迁移，外部原始库只读提取，规则见 [任务导航](AGENT_WORKFLOW.md)。

## 五个阶段

| 阶段 | 要做什么 | 完成条件 |
| --- | --- | --- |
| 战斗逻辑 | 在逐卡定义注册数据，复用通用单位/技能系统；新字段补读取、校验和必要回归 | 生成、目标、伤害、时序与必要联网正确 |
| 模型动画 | 接包装场景，校正比例、脚底、朝向和实际动作 | 双方/形态及连续动作完成目视，不用动画决定伤害 |
| 卡面 | 优先原生加载图，其次模型摄影，最后生成图 | 牌库、详情、手牌显示正确 |
| 音频 | 按已实现动作找声音，记录来源、变体、处理和停止条件 | 实战触发、命中、暂停恢复、死亡及清场试听正确 |
| 联合验收 | 跑核心回归，实战观察与试听；改联网事件时检查主客双方 | 更新当前手册，明确缺项，不将未验证写成通过 |

具体流程：[卡牌机制](CARD_DESIGN.md)、[美术接入](ART_PIPELINE.md)、[音频接入](AUDIO_INTEGRATION.md)。普通新卡自动进入内容契约；只为独特机制、时序或生命周期增加专项测试。

## 交付前

```sh
python3 tools/maintenance/audit_project.py
Godot --headless --path . --editor --import --quit
Godot --headless --path . --script tests/mechanics_check.gd
git diff --check
```

检查最终“全部通过”和错误日志，不能只看退出码。完整命令与联网/渲染要求见 [测试手册](../tests/README.md)。

总览写中文数值与玩法，动画/音频/特效各自说明；强关联互链，蓝红合篇。素材处理记录留在素材目录，已结束过程归档；截图录音可放 `builds/` 或临时目录，源模型和来源清单不能当缓存删除。
