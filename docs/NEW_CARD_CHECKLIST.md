# 新卡与素材接入清单

完整新卡按 **战斗逻辑 → 模型动画 → 卡面与技能图标 → 音频 → 联合验收** 推进。只替换某类素材时执行对应阶段，不顺带改变玩法。

## 开始前

1. 检查现有修改，确定卡牌身份、费用、定位、主动候选和可复用机制。涉及控制或加成时，按[状态与效果规则](status/README.md)填写最小定义单，并先核对实际支持；草案不代表已经实现。
2. 确定稳定英文标识，建立 [单位总览](units/README.md)，使用 [模板](templates/card.md)。
3. 确认素材来源和依赖；先在开发素材库内候选讨论或制作中归档，用通用展台选择，需要实战时在素材库内联调副本试接入。阶段迁移规则见 [任务导航](AGENT_WORKFLOW.md)。

## 五个阶段

| 阶段 | 要做什么 | 完成条件 |
| --- | --- | --- |
| 战斗逻辑 | 在逐卡定义注册数据，复用通用单位/技能系统；新字段补读取、校验和必要回归 | 生成、目标、伤害、时序与必要联网正确 |
| 模型动画 | 接包装场景，校正比例、脚底、朝向和实际动作 | 双方/形态及连续动作完成目视，不用动画决定伤害 |
| 卡面与技能图标 | 卡面优先原生加载图，其次模型摄影，最后生成图；英雄主动技能有对应 LoL 原版图标素材就直接接入，没有则保留文字占位并记录缺项 | 牌库、详情、手牌显示正确；信息面板技能名称前与战斗技能按钮的图标、技能切换及占位正确 |
| 音频 | 按已实现动作找声音，记录来源、变体、处理和停止条件 | 实战触发、命中、暂停恢复、死亡及清场试听正确 |
| 联合验收 | 跑核心回归，实战观察与试听；改联网事件时检查主客双方 | 更新当前手册，明确缺项，不将未验证写成通过 |

具体流程：[卡牌机制](CARD_DESIGN.md)、[美术接入](ART_PIPELINE.md)、[音频接入](AUDIO_INTEGRATION.md)。普通新卡自动进入内容契约；只为独特机制、时序或生命周期增加专项测试。

## 主动技能图标

新增英雄卡牌或补充主动技能时，逐个核对当前技能对应的 LoL 原版技能与形态，并查找本地素材库。有对应原版图标素材就直接使用，不等后续美术轮次；没有对应素材则沿用现有文字占位，不用其他技能图标猜配。

正式 PNG 放 `assets/skills/`，在该卡 `visual.active_skills` 的对应索引配置 `icon_path`，与 `gameplay.active_skills` 数量、顺序一致；来源与哈希登记到技能图标来源清单。缺素材时省略字段，交付中记录占位项。提取与接入方法见 [美术流程](ART_PIPELINE.md#主动技能图标) 和 [现有素材记录](../assets/skills/README.md)。

验收覆盖信息面板名称前、战斗技能按钮、多个技能切换，以及无图标占位；实际渲染检查可用、待释放和禁用状态。法术沿用现有出牌机制，不为展示图标另加释放入口。

## 交付前

```sh
python3 tools/maintenance/audit_project.py
Godot --headless --path . --editor --import --quit
Godot --headless --path . --script tests/mechanics_check.gd
git diff --check
```

检查最终“全部通过”和错误日志，不能只看退出码。完整命令与联网/渲染要求见 [测试手册](../tests/README.md)。

总览写中文数值与玩法，动画/音频/特效各自说明；强关联互链，蓝红合篇。素材处理记录留在素材目录，已结束过程归档；截图录音统一放项目根目录素材库 `04-中间产物/`，源模型和来源清单不能当缓存删除。

定义字段归属、主动技能表现列表与变形四域写法见[原始定义契约](CARD_DESIGN.md#原始定义的四域契约)。先通过域和类型检查，再进入模型、音频与战斗验收。
