# 交付合同：工程审查 E3 — Mac 导出与启动闭环

- **需求 / 来源**：[CL-14](../issues/2026-09-14_工程审查报告.md)，当前 Mac 为目标，手机不列入本轮发布目标。
- **完成结果**：`godot-version.txt` 固定 Godot `4.7.1.stable.official.a13da4feb`；统一 GL Compatibility 标签，纳入不含凭据的 `export_presets.cfg`，启用官方 universal 模板所需的两类纹理压缩导入。模板版本与官方 SHA512 已核验。新增可追溯导出脚本、签名校验和发布包内命令行冒烟入口；正常菜单不运行诊断。
- **启动修复**：直接 `--mode=local` 启动曾只有随机显示手牌、没有权威卡组，导致无法出牌。现在先确定同一份默认八卡卡组，再建立玩家、AI 和显示循环；菜单选定的卡组不被替换。三条改前失败回归覆盖手牌一致、扣费轮换、真实生成；见 [改前反例](../../ClashLegends-开发素材库/04-中间产物/构建与验证/verification/local-deck-before.log)。
- **验证**：基线 `5eab9a30fd4f380464fd1c111534db62387c6afe`，工作区含既有及本轮修改。默认卡组修复后的 3187 项机制断言、20 项工具测试、七组联网场景通过，且运行期间工作区不变，见 [结果](../../ClashLegends-开发素材库/04-中间产物/构建与验证/verification/20260914-145945-382694/result.json)。最终发布包完成导入、导出、ad-hoc 签名校验、菜单与单机探针，见 [导出结果](../../ClashLegends-开发素材库/04-中间产物/构建与验证/macos/20260914-144637-192616/result.json)。单机探针实际检查四张显示/权威手牌、扣费、轮换、生成及终局音频停止，再释放场景后退出；不会只凭退出码 0 宣布成功。原始失败记录保留，包括导入设置变化使验证无效、外部脚本未执行和强制退出时的音频引用错误。
- **查看方式**：打开 [Clash Legends.app](../../ClashLegends-开发素材库/04-中间产物/构建与验证/macos/20260914-144637-192616/Clash%20Legends.app)，或按 [复现说明](../../tools/release/README.md) 重建。原生窗口的地图、塔、兵线、手牌和终局已目视检查；实际鼠标终局按钮可重新加载场景（命令行启动保留其 local 参数，会直接进入下一局）。
- **遗留 / 未验证**：仅 M5 Mac 实测，universal 包中的 Intel 分支未验收；本机 ad-hoc 包未公证，不作为公开发行认证。原生鼠标出牌自动化未形成可靠通过证据；显示层按钮选择已通过引擎 GUI 事件探针，发布包内出牌事务通过，不把它们冒充完整人工交互确认。声音主观听感未获用户确认。强制退出引擎时正在启动的声音可留下退出清理日志，正常终局停止已覆盖；本轮未修改 Godot 引擎。
