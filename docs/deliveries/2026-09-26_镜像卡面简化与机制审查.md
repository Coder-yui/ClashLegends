# 交付合同：镜像卡面简化与机制审查

- **需求 / 来源**：用户对话；简化镜像卡面，主动排查实现漏洞并修复。
- **完成结果**：AI 生成并接入银色镜子、金卡与青色倒影的简化卡面；旧图归档到本地素材库。来源与完整提示词见 [素材记录](../../assets/cards/mirror_source.md)。协议版本由 65 升至 66，双方需使用同版。

## 发现与修复

| 问题 | 触发与结果 | 修复 |
| --- | --- | --- |
| 较早镜像法术丢失强化 | 两次镜像都在排程中时，较早代次被降为普通槽，已付款治疗的过量护盾消失 | 代次只控制单位的技能槽所有权，已接受法术保留强化 |
| 联网预览与复制目标不一致 | 原卡请求未确认时再发送镜像，客户端仍按旧历史显示目标和费用 | 原卡请求待确认期间禁用镜像选择，并在请求入口拦截；确认或拒绝后恢复 |
| 进阶形态卡面错误 | 复制蓝凯等形态时，显示基础卡牌纹理 | 动态卡面使用历史锁定的实际部署形态，保持镜面标记 |
| 通用联网测试受注册顺序影响 | 新英雄排在数据库前面，测试盖伦不在主动槽，无法完成技能会话检查 | 测试夹具显式固定八卡与盖伦技能；不改变正式规则 |

另外检查了：无历史与不足费拒绝不消费手牌、双方历史隔离、基础费用与主动法术加价区分、付款时锁定天使形态、随机首手排除镜像、最多左右两槽、旧复制体存活但失去资格、延迟落地不能抢回槽位、复制建筑挪位、编队队长死亡转交、工作台技能选择、资源依赖闭包与模型池容量。上述覆盖用例通过；未发现新的问题。
