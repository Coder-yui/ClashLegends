# 交付合同：工程审查 B4b — 建筑部署占位

> 本文记录的预留方案已被用户最新规则替代，现行实现见[建筑落地挪位](2026-09-14_建筑落地挪位与塔墟规则.md)。

- **需求 / 来源**：[工程审查 CL-05](../issues/2026-09-14_工程审查报告.md)与用户澄清：保留现有塔墟部署设计，解决等待生成的建筑占位竞争，不基于假设新增退款或自动挪位玩法。
- **完成结果**：CommandSchedule 持有 DeploymentReservations。建筑在扣费前预留完整部署矩形，重叠请求立即拒绝且不扣费、不轮换；付款失败释放。命令与预部署阶段传递同一令牌，最终生成核对令牌及占地所有权，低层生成也不能侵入其他预留；兑现或清场后释放。令牌不在清场时复用，旧命令重放不能生成第二栋建筑。预留不写导航，不阻挡行军。规则协议升为 17。
- **塔墟边界**：活塔阻挡；太阳圆盘中心进入已毁公主塔九格才获特殊部署资格，擦边仍拒绝。穷举双阵营全部格心证实活塔变塔墟不会使原先合法的太阳圆盘落点失效。因此采用“接受时合法 + 持续独占预留 + 生成时校验令牌”的保证，不把正常命令改成等待后可能因塔墟变化被撤销，也不新增建筑退款/手牌恢复规则。当前没有塔复活、建筑移动等破坏此保证的机制；未来引入时须同时扩展命令规则。
- **验证**：基线 `5eab9a30fd4f380464fd1c111534db62387c6afe`，保留既有未提交修改；Godot `4.7.1.stable.official.a13da4feb`。改前 `builds/review-fixtures/cl05-baseline.log` 复现墓碑和太阳圆盘在同一落点均被接受。修复后 2318 项机制断言、18 项工具测试及七组双进程场景全部通过，见 [完整结果](../../ClashLegends-开发素材库/04-中间产物/构建与验证/verification/20260914-124124-540024/result.json)。新增联网场景由客户端连续提交同位置两张建筑，双端均仅有一个墓碑、金币从 10 变 7、太阳圆盘仍在手牌。共边允许、重叠拒绝和重复释放另外通过 `builds/review-fixtures/reservation-adjacency.log` 夹具。
- **查看方式**：运行 `python3 tools/verify.py --network-boundaries`；正常对战在第一座建筑生成前尝试重叠部署第二座，后者不会扣费或生成。
- **遗留 / 未验证**：当前建筑定义没有出现前预部署时长；该通用路径通过两段式排程夹具验证，未声称存在一张现用两段式建筑。未做人工触屏验收，当前发布目标为 Mac。C/D/E 板块仍继续处理。
