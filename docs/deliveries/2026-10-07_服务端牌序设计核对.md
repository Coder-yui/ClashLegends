# 交付合同：服务端牌序设计核对

- **需求 / 来源**：用户对话；讨论联网改善方法，核对初始四张手牌与八张卡牌轮转的权威归属。
- **完成结果**：只读核对，未修改规则。服务器为双方分别建立CardCycle并随机初始顺序，前四为手牌、后四为待抽队列；开局仅向对应玩家发送其hand/queue，接受出牌后权威轮换并可靠回执。下一张是队首，出掉的牌进入队尾。玩家选择使用哪张牌会影响后续轮转，不是机械重复最初八张排序。镜像不得进入首手；备战前两槽的主动资格不随洗牌改变。
- **验证**：阅读scripts/battle/card_cycle.gd及main.gd的服务器初始化、running、出牌验证/消费/回执、CardHand显示路径。未修改可执行代码，未重跑机制回归；本轮不以既往测试冒充新验证。
- **查看方式**：直接查看本文。
- **遗留 / 建议**：客户端初始化及回执仍会创建临时随机CardCycle，随后被服务器状态覆盖，不影响正式牌序权威；可收敛成纯副本初始化。当前本方完整四张待抽队列也下发，UI仅显示队首，对手不接收本方手牌与队列；如果需要严格最少信息，可只下发四张手牌与下一张。未来增加手牌状态版本、已处理请求序号，以及与战斗随机隔离的每局洗牌随机源和服务器日志，便于重连/复现。本轮未实施这些建议。

联机建议：继续使用权威服务器与快照表现；优先优化本地即时操作反馈及根据抖动调整表现缓冲。暂不引入客户端战斗预测/回滚。0.5秒操作缓冲和表现缓冲分别承担请求排程与下行平滑，不保证无限延迟下的同步。一般预测/插值方法参考[Valve联网说明](https://developer.valvesoftware.com/wiki/Source_Multiplayer_Networking)。
