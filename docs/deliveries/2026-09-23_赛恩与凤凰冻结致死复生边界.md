# 交付合同：赛恩与凤凰冻结致死复生边界

- **需求 / 来源**：用户对话。赛恩第一条命在冰冻中被击杀，应立即解除模型定格进入复生；血条在复生动作内从0逐渐填满。冰晶凤凰冻结中死亡变蛋遵循同样边界。
- **完成结果**：提交致死结算时由ControlState清除旧冰冻/眩晕，不将硬控带入下一条命。赛恩的致死动作取消及表现优先级直接接管冻结姿势，不先绕到Idle、不恢复旧攻击；客户端也不让旧控制覆盖复生。凤凰立即生成未继承旧硬控的蛋，落地过渡正常推进；被冰冻的蛋击破后，凤凰死亡后续播放器显式恢复正常播放速率。普通存活换形的冻结规则不变。
- **血条**：2秒复生等待按权威40Tick计时显示0→满血，帧间只允许一个Tick的平滑外推；客户端晚到按快照进度显示。真实生命在等待阶段保持0，仍拒绝敌我交互及治疗，完成后才真正恢复满血。凤凰蛋继续显示自己的真实血量。
- **验证**：基线4ca4f25，Godot 4.7.1 stable（a13da4feb）；工作区含其他未提交修改，已保留。联调副本的赛恩、凤凰、动画状态与网络生命周期专项181项断言通过，覆盖多来源冰冻、叠加眩晕、冻中致死、蛋的新冰冻、蛋冻中击破、血条半程、无新快照外推限制。正式工程全量回归**6576项断言通过**，无脚本或资源错误（[日志](../../ClashLegends-开发素材库/04-中间产物/构建与验证/冻结致死复生-20260923/regression_final.log)）。首轮发现默认卡组测试随机到潘森时没有等待0.6秒预部署，已按卡牌实际预部署窗口修正测试等待时间。实际渲染复现两者第一条命仅剩1血、8秒冰冻中致死：赛恩立刻播放Passive_Death，1秒时血条约50%且真实生命为0；凤凰已变为地面蛋。真实双进程联机确认客户端零血等待时解除冻结且显示中途血条（[客户端日志](../../ClashLegends-开发素材库/04-中间产物/构建与验证/冻结致死复生-20260923/network_client.log)）。审计与git diff --check通过。
