# 交付合同：建筑到期与击退接管边界修复

- **需求 / 来源**：用户对话，仅处理建筑自然到期的攻击资格与多次击退接管；完成后提交并推送。
- **完成结果**：两个边界分别复现、修复和回归。建筑修复提交 `881945a`；击退修复提交 `1924b92`。保留已有未提交的卡牌音频、素材、交付文档、工作台及并行治疗任务修改，不纳入本轮提交。

## 根因与规则

建筑寿命原本在每个 Unit.sim_tick 内扣减，攻击者先更新时仍能向即将自然消失的目标出手并获得收益。现由 Main 固定 combatants 快照，在攻击收集前只推进建筑自然寿命/衰减及退出；行动阶段跳过重复寿命推进。部署未结束和 Tick 起点的冻结/眩晕仍暂停寿命，部署最后一个正常 Tick 推进一次。控制、召唤计时不在预处理推进。到期建筑不攻击、不首次或周期召唤，解除导航和退出只执行一次；其死亡生成对象不回到本阶段快照。自然衰减不算受击，原有死亡效果触发规则不变。

伤害结果分为 accepted（请求接受）、landed（提交扣血前统一冻结的合法命中）和 health_lost（实际掉血归属）。存活目标的全盾吸收仍是合法命中；自然失效目标不发放命中收益。本批其他刀造成的死亡不撤回本批合法命中，实际掉血仍按既有比例分摊，死者仍不获得存活收益。

多次击退原本按回调收集顺序覆盖，且直接入口未拒绝死亡目标。现先验证合法性，再从当前位置替换旧位移状态与尚未消费的移动意图；短、弱位移也接管，不叠加、不恢复旧位移。无异步完成回调，因此没有新增回调代次机制。跨 Tick/阶段保持现有先后；同阶段按 `[战场出生身份, 来源内事件序号, 效果子序号]` 升序提交，最后合法事件接管。身份在对象接入战场时确定，普攻发射/技能排队保存事件序号，弹体携带原事件身份。测试改变收集/节点排列时保留这些身份；改变身份属于改变权威事件顺序。这是项目平手约定，不是对 LoL 内部服务器算法的声明。

规则协议从 20 升至 **21**；快照载荷仍为版本 20。客户端不重算击退，只应用权威位置与可靠生命周期。

## 修改与回滚范围

- 建筑单元：`Main._sim_step`、`Unit.prepare_natural_lifecycle/_building_tick`，以及 CombatResolver、BattleNumbers、Unit/Tower 的命中结果契约；回归为 `BuildingExpiryBoundarySuite`。
- 击退单元：Unit 的合法性与状态替换、CombatResolver 排序队列，ProjectileSystem 发射身份、技能排队/范围击退和战场出生注册；回归为 `KnockbackBoundarySuite` 与双进程 integration fixture。
- 规则更新见 [卡牌机制](../CARD_DESIGN.md)、[维护架构](../MAINTENANCE_ARCHITECTURE.md)、[测试手册](../../tests/README.md)。整体回滚按 `1924b92`、`881945a` 逆序撤销；若仅回滚某一边界，应保留另一边界在共享 Main/Unit/CombatResolver 中的改动并重新验证，不能只还原单个公共文件。
- 不改变 20Hz、数值、寻路、素材、同批互换、真实先手、剑圣三段循环与追加刀速率/取消边界、双水晶平局及爆炸后结果音频。覆盖位移不撤销伤害、护盾、冻结/眩晕/减速或已提交追加刀。工作台仍仅作预览。
