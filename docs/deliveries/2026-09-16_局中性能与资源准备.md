# 交付合同：局中性能、资源准备与工程精简

> 后续加载策略已收紧，当前结果见[缩短开局准备](2026-09-16_缩短开局准备.md)；本文保留本轮历史测量。

- **需求 / 来源**：用户对话及附件。优先减少局中首次/重复生成成本，保持20Hz权威模拟、完整同Tick结算、画质与音频数量。
- **基线 / 环境**：`c87f21829405100f83c5a82bf4eaf441ad351e27`；开始时工作区干净。Godot `4.7.1.stable.official.a13da4feb`，Apple M5 / 16 GiB，默认`gl_compatibility`（实机日志OpenGL 4.1 Metal）。保留过程中用户新增的需求文档，没有提交Git或覆盖这些文件。

- **测量纠错**：旧基准第300帧同步写PNG，会制造约269ms慢帧及模拟追赶。已将截图移至计时结束；只有`capture_policy=after_measurement`的数据进入最终对照。没有排除出牌、召唤、变形产生的慢帧。旧实验保留，但不用于最终最大帧结论。

- **解释**：收益主要是消除昂贵初始化尖峰，未证明一般帧P95改善或稳定60 FPS。正常对局280次单位模型领取零缺货；小鬼80次、两阵营近战兵合计36次均复用。先锋8次、蠕虫48次领取零缺货，蠕虫峰值并发24。附属强化效果仍有66次轻量即时创建，记录总实例化约1.7ms，未把它们说成零分配。
- **剩余尖峰**：12纳尔压力超出每方2份合理库存，生成/变形仍各约380ms，最大帧约420ms，后备路径不延迟权威事件。正常对局新最大帧40.55ms位于Tick2246，该轮模拟最大18.58ms、导航最大7.91ms；这说明仍有绘制/调度和一般导航成本，现有采样不足以将每个剩余慢帧精确归因，未为此扩展重型分析。
- **加载代价**：正常对局4.65→10.31秒；当前场景建立0.666秒、资源累计0.630秒、模型实例化/ready 0.098秒、动画库准备1.465秒、样本准备0.360秒、590次实际绘制4.862秒。资源累计与场景/准备有重叠，不能简单相加。展示补时0、单机等待对手约0；原版未记录这些分段，不补造前值。
- **内存代价**：正常对局Godot静态峰值382.6→444.6 MiB，退出165.6→167.6 MiB、对象1875→1876；当前加载后431.9 MiB/7801对象，局中峰值8270对象。进程RSS峰值719→724 MiB。先锋静态峰值370.7–371.1→411.0–411.4 MiB；12纳尔498.9→527.1–527.5 MiB。RSS压力结果波动较大（先锋704–902→662–963 MiB，纳尔690–1066→807–1103 MiB），不据此宣称内存下降。
- **按用户收缩验证范围**：原版第二轮完整对局已结束（帧P99 30.10ms、最大219.28ms）；修改版第二轮中止，不计入结果。停止后续同进程重进和显式无预热测量，入口已经实现，但本次不宣称这两项图形验收通过，也不以单次退出证明长期无泄漏。加载取消、返回重开及60次模型复用已有机制/联机回归。
