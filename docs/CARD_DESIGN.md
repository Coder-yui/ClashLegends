# 卡牌设计手册

> 新增卡牌前必读。所有卡牌数值统一定义在 `scripts/data/card_db.gd` 的 `CardDB.all()` 中。

## 一、卡牌类型（type）

| 类型 | 说明 | 部署规则 |
|---|---|---|
| `"unit"` | 战斗单位（默认，可省略不写） | 我方半场 |
| `"spell"` | 法术，不生成单位，直接在目标点生效 | 全场任意位置 |
| `"building"` | 建筑卡，不可移动，有存活时间 | 我方半场 |

## 二、属性一览

### 基础属性（所有卡）

| 属性 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | String | ✅ | 显示名（中文） |
| `cost` | int | ✅ | 金币费用（参考曲线见第四节） |
| `type` | String | | `"unit"` / `"spell"` / `"building"`，默认 `"unit"` |
| `color` | Color | ✅ | 占位图颜色（阶段 4 替换为美术） |
| `selectable` | bool | | 是否进入玩家/AI 卡池，默认 true；仅纯系统单位设为 false |

### 战斗属性（unit / building）

| 属性 | 默认值 | 说明 |
|---|---|---|
| `hp` | 100.0 | 生命值 |
| `damage` | 10.0 | 单次攻击伤害（`is_continuous_attack` 时为每秒伤害） |
| `range` | 30.0 | 攻击距离（与目标体积边缘的距离）。近战 24~32，远程 100~130 |
| `speed` | 50.0 | 移动速度。慢 40-50 / 中 50-65 / 快 65-85 / 冲锋 >90 |
| `interval` | 1.0 | 攻击间隔（秒），越小攻速越快 |
| `first_hit` | interval × 0.5（通常最多 0.4） | 动画开始到攻击生效节点的时间：近战为命中，远程为弹体离弦/生成，可按素材覆盖 |
| `deploy_time` | 1.0 | 单位生成后的部署时间（秒），期间不移动、不索敌、不攻击，但仍可碰撞、被索敌和命中 |
| `size_tier` | `medium` | 单位体型档位：极小 / 小 / 稍小 / 中 / 稍大 / 大 / 极大 |
| `radius` | 14.0 | 由体型档位选用对应常量，影响碰撞、部署、寻路、推挤与攻击接触距离 |
| `mass` | radius ÷ 3 | 推挤质量；质量越大，被单位碰撞和击退移动的距离越小 |
| `projectile_speed` | 0 | 大于 0 时使用可飞行、追踪目标的主机权威弹道；0 为近战/即时命中 |
| `projectile_visual` | `"orb"` | 弹体表现类型；当前支持普通圆点 `orb`、寒冰 `arrow`、提莫 `needle`，只影响绘制 |
| `projectile_visual_height` | 0 | 弹体相对地面原点向上的屏幕绘制高度；只修正弓/枪口位置，不参与碰撞与命中 |
| `projectile_visual_forward_offset` | 0 | 弹体第一帧相对单位的前向绘制偏移；用于权杖/炮口，只影响表现并沿航程收敛 |
| `projectile_colors` | `[]` | 可选的 `[蓝方, 红方]` 弹体颜色；不配置时沿用单位 `color` |
| `attack_pattern` | `[]` | 可选的连续攻击命中间隔数组；瑟提用它表达“两拳→停顿”的循环，空数组仍使用固定 `interval` |
| `splash_radius` | 0 | 命中点范围伤害半径，按目标碰撞圆相交判断 |
| `knockback` | 0 | 命中时基础击退距离，会再按目标质量衰减 |
| `charge_time` | 0 | 连续移动达到该秒数后进入冲锋；0 表示无冲锋 |
| `charge_speed_multiplier` | 1.0 | 冲锋移动速度倍率 |
| `charge_damage_multiplier` | 1.0 | 冲锋首次命中的伤害倍率 |
| `transform_after_hits` | 0 | 大于 0 时，每次普通攻击真正命中后计数，达到次数切换到 `transformed_stats` |
| `transformed_stats` | `{}` | 双形态单位的第二形态战斗数据与表现映射；变形保持同一单位、`net_id` 和主动归属 |

所有手牌在确认和扣费后统一等待 0.5 秒才生成或生效；`deploy_time` 是兵种生成之后的
另一段计时。完整时序、部署期间交互和动画接入约定见
[`UNIT_DEPLOYMENT.md`](UNIT_DEPLOYMENT.md)。

模型单位可在 `visual_animations` 中配置 `death_duration`。它只改变 Death 素材的播放
速度和视觉代理清理时间，不延迟权威死亡、占地释放或联网同步。当前英雄统一为 0.8 秒，
近战兵、远程兵、炮车兵和超级兵统一为 0.5 秒。

### 行为标记（unit / building，均可省略，默认 false）

| 属性 | 说明 |
|---|---|
| `is_air` | 空中单位：无视河道/障碍直线飞行，地面近战打不到它 |
| `can_attack_air` | 能对空：可以选中并攻击空中单位（远程单位一般都该给 true） |
| `building_only` | 只攻击建筑（塔+建筑卡），无视敌方单位（攻城单位用，如盖伦） |
| `is_building` | 建筑卡标记（type 为 building 时必须给 true） |
| `is_continuous_attack` | 持续攻击（DPS 模式）：每帧造成 `damage × delta`，无需 `interval` |

### 建筑卡专属

| 属性 | 说明 |
|---|---|
| `lifespan` | 存活时间（秒），期间血量持续流逝，到时自动消失 |
| `spawn_interval` | 生成间隔（秒），每隔这么久生成一批小鬼（属性见 `CardDB.imp_stats()`） |
| `spawn_count` | 每批生成数量；墓碑为 2 |
| `spawn_side` | 生成侧；`map_side` 表示按墓碑位于地图左/右半区固定在对应侧生成 |

### 法术卡专属

目前法术只有冰冻（`"freeze"`），属性直接在 `_cast_spell` 中读取：

| 属性 | 说明 |
|---|---|
| `radius` | 影响范围半径 |
| `duration` | 冰冻持续时间（秒） |

新增其他法术需要在 `main.gd` 的 `_cast_spell()` 里加一个 `match` 分支写效果逻辑。

## 三、主动技能与卡组前两槽

- 备战界面采用两步操作：点击已占用卡槽中的卡牌后显示“信息 / 移除”，点击下方未入组卡牌库中的卡牌后显示“信息 / 添加”；点击同一张牌会收起操作项。空卡槽显示“+”，选中空槽后再点击牌库卡牌会直接放入对应位置。
- 牌库支持按全部、地面、空军、建筑、法术筛选，默认按名称排序，也可按金币消耗递增或递减排序；已加入卡组的卡牌从牌库隐藏，移除后恢复显示。
- “信息”页展示简介、费用、类型、生命、伤害、攻击间隔、距离、速度、视野等适用数值，以及从权威数据字段生成的特殊机制说明。页面同时提供主动技能和皮肤选择；当前所有卡只有一个主动技能，默认皮肤名称为“原皮”。
- 备战卡组仍为 8 张，只有顺序中的第 1、2 张会把主动版本带入对局；其余 6 张仍按普通版本轮转。
- 单位卡和建筑卡从主动位打出后，会在战场底部对应的固定圆位显示一次性主动技能图标：槽 1 在左、槽 2 与它关于战场中线严格镜像。技能使用或该实例死亡后图标消失；场上没有可用主动实例时不显示空圆圈。
- 每个主动槽只绑定最近一次部署的实例。同卡速转再次部署时，新实例立即覆盖旧实例的未用资格；旧实例仍可正常战斗，但不能再释放主动技能。
- 点击主动按钮后进入固定 0.5 秒待释放窗口，期间按钮显示等待态；技能只在主机固定步进达到释放时刻后结算，用来统一单机与联机手感并为网络延迟留出窗口。
- 法术卡不生成按钮。法术位于前两槽时，打出即自动结算主动版本。
- 单机 AI 与玩家遵守相同的前两槽规则；当前占位 AI 会在主动单位/建筑生成后发起使用，并同样等待 0.5 秒结算。
- 联机时客户端按钮只发送 `ability_id` 请求；主机使用客户端已登记的完整卡组、前两槽和实例归属再次校验，通过后进入 0.5 秒权威队列，再进行伤害、护盾、召唤、击退、减速或增益结算。
- 当前每张英雄/单位/建筑卡只设计一个主动技能。未来一张卡可以通过 `active_skills` 提供多个候选技能，玩家在信息页选择其中一个；选择结果会随联机卡组登记，放入主动槽后只携带这一项，单局不会让同一张卡同时获得多个主动按钮。

当前非纯法术卡在 CardDB 中提供单个 `active_skill`；未来可扩展为 `active_skills` 候选集合，但一局仍只携带其中一个：

| `kind` | 通用字段 | 效果 |
|---|---|---|
| `buff` | `duration`、三个 `*_multiplier`、可选 `shield` | 强化该部署实例的移动、伤害、攻速并可加护盾 |
| `nova` | `radius`、`damage`，可选 `knockback` / `slow_*` / `shield` | 以该实例为中心命中范围内敌人 |
| `summon` | `spawn_id`、`spawn_count` | 通过 `spawn_summoned()` 在该实例周围生成召唤物 |
| `dual_form` | `length`、`width`、`damage`、`stun_duration` | 初始形态立即变身；第二形态向前方矩形区域造成伤害并眩晕地面敌人 |

### 单位体型档位

体型是权威战斗数据，不只是模型大小。人物模型统一应用当前 `1.5×` 全局倍率，七档
碰撞半径则在放大结果上统一减去 3px，并使用 `CardDB` 常量，不在卡牌里另写相近但
不相等的半径。权威碰撞形状是竖直圆柱，
俯视模拟以它的圆形底面参与碰撞、寻路和攻击接触判定：

| 档位 | `size_tier` | 碰撞半径 |
|---|---|---:|
| 极小 | `SIZE_EXTREMELY_SMALL` | 9 |
| 小 | `SIZE_SMALL` | 12 |
| 稍小 | `SIZE_SLIGHTLY_SMALL` | 15 |
| 中 | `SIZE_MEDIUM` | 18 |
| 稍大 | `SIZE_SLIGHTLY_LARGE` | 21 |
| 大 | `SIZE_LARGE` | 24 |
| 极大 | `SIZE_EXTREMELY_LARGE` | 27 |

当前分档：大纳尔=极大；盖伦=大；瑟提、龙王=稍大；剑圣、寒冰、赵信、格温、超级兵=中；
炮车兵=稍小；近战兵、远程兵、提莫=小；墓碑产出的小鬼=极小。`mass` 仍单独配置，体型变化不会
自动修改血量、伤害或推挤质量。

### 双形态与眩晕（纳尔）

纳尔以小纳尔形态生成。普通攻击只有在主机权威命中出口真正造成伤害后才累计一次；
回旋镖离手、目标在途中死亡或攻击失效都不计数。小纳尔第 6 次命中后立即切换到
`transformed_stats`；大纳尔第 4 次命中后立即切回基础形态，两边命中计数各自从 0 开始。
在途回旋镖保存出手时的形态编号，若命中时纳尔已经变大，不会误计入大纳尔的 4 次命中。

变大时最大生命从 430 提升到 820，当前生命增加两形态上限差值 390；变小时最大生命恢复
430，当前生命保持大纳尔的剩余值，但最多为 430。射程、视野、质量、速度、对空规则和
权威碰撞半径都在触发命中的同一模拟帧切换。半径采用瞬时切换以保证主机判定确定；若小
纳尔所在位置对半径 27 不再合法，主机把它修正到最近的合法地形点，随后仍由统一单位推挤
解决活动单位重叠，避免在河岸、桥角或塔边永久卡住。密集四向包围与贴场地边缘变大的
回归用例会验证：变大当帧开始按质量推开邻近单位，最终所有圆柱分离且仍在合法地形内。

普通变大锁攻击 1.50 秒：`Rage_Scale` 不是可单播的完整动作，而是相对单帧
`Rage_Scale_Base` 的加法缩放层；运行时把它与 `Rage_Move` 的完整骨骼姿势合成为同一段变身动画。
普通变小同理，把 `Revert_Scale` 相对 `Scale_Base` 的差值叠加到 `Gnar_Revert`，完整时长约
1.33 秒。这样形变过程中身体保持正常展开，不会因绑定姿势缺少旋转轨道而挤成一团。
由于源游戏两套模型比例与本项目包装尺寸不同，合成时还会重映射相关根缩放轨道的首值：
变大首帧按小纳尔包装尺寸显示、末帧精确回到大纳尔尺寸；变小首帧按大纳尔尺寸显示、
末帧回到小纳尔基准缩放。动作姿势会令投影宽高略有差异，但不会再从过小或过大的倍率起步。
三段变身合成动画会隐藏石头/额外回旋镖；大、小纳尔的 `Run_In` 也沿用相同过滤，进入
`Run_Base` 后恢复完整模型。
形态数值先切换，所以演出期间立即按新形态视野和射程
决定下一步：目标在圈外则可以继续移动，进入圈内则原地等待且预装填攻击；演出结束的同一
模拟帧直接开始攻击。冰冻/眩晕会同时暂停演出动画和固定锁定计时。大、小纳尔从非移动状态
进入移动都先播各自 `Run_In`，再循环 `Run_Base`。

纳尔主动技能仍遵守主动槽一次性和 0.5 秒主机权威待释放规则。小纳尔释放时立即变大并
启动前方 Spell2，把 `Rage_Scale` 加法层与 `GnarBig_Spell2_Tran` 同步合成为一段 1.20 秒
变身施法动画；在施放后 0.80 秒手掌触地时才结算。大纳尔释放时直接播放
`GnarBig_Spell2`，同样在 0.80 秒触地帧结算。
蓄力期间显示 120×160 的半透明三边矩形：保留两侧和远端宽边，靠纳尔的近端宽边不画线。
发动技能的同一模拟帧固定朝向；整段技能动画期间不能自主移动或普通攻击，范围框和触地命中
始终沿该固定方向。技能按触地时目标碰撞圆与前方有向矩形相交判定，只命中地面目标，造成
伤害并施加 1 秒 `stun_timer`。冰冻/眩晕会同时暂停技能动画、施放锁、范围框计时和触地结算。
变形演出或技能施放期间不能再次使用主动技能。小纳尔普攻使用非 Fast 版
`Gnar_Attack1` / `Gnar_Attack2`。

大纳尔攻击塔或建筑卡时使用 `attack_structure` 映射的 `Turret_Attack`，攻击普通单位仍
使用常规 `attack`；目标类型由主机随快照同步。大纳尔死亡先完整播放约 0.27 秒的
`GnarBig_Death`，再换成小纳尔模型播放 `Death`。这些动画均只消费权威状态，不反向参与
索敌、伤害或死亡。大纳尔半径为 27，是当前可移动单位唯一的“极大”档；盖伦为 24。

### 分段普通攻击表现（瑟提）

`attack_pattern` 只控制主机权威的命中间隔；素材需要由 Start、Hit、收势多段动画组合时，
可在 `visual_animations` 中额外配置同长度数组：

- `attack`：每一拳命中前播放的 Start；
- `attack_hit`：权威命中时切入的 Hit / Passive 动作；
- `attack_recover`：可选收势，空字符串表示该拳没有独立收势；
- `attack_recover_delay`：命中后经过多久切入收势。
- `deploy_clip_ratio`：单段部署动画可选的开头播放比例；例如 `0.5` 表示部署窗口只播放前半段，结束后直接交还普通状态机。

这些字段只由 `UnitModel3D` 播放，不能驱动伤害。瑟提当前四步依次为第一套左拳、第一套
右拳、第二套左拳、第二套右拳；每个右拳后用对应的 `Passive_Into_Idle` 表现停顿。

### 丝缕缠流（格温）

格温首次普攻**命中**后开启；此后以自身为圆心、`shroud_radius`（默认 2.5 格 = 100px）为半径，**半径之外的所有敌方（单位与塔）都看不到她**：索敌时不把她当目标、不会攻击她，也没有命中判定，照常去处理其他事；敌方进入圈内即可看到她并攻击。格温失去丝缕缠流状态时，敌方恢复正常索敌与攻击。

- **开启时机**：首次普攻真正造成伤害后，由主机命中出口调用 `on_attack_landed()`；
  出手、弹体离弦或被免疫的攻击都不算命中。
- **关闭时机**：退出攻击状态即关闭 —— 目标死亡/脱离攻击圈回到行军、被击退、目标失效都会重置为关闭。格温须重新进入攻击并命中才再开。
- **判定依据**：
  - 索敌侧：敌方（单位/塔）在 `_find_nearest_distraction` / `_find_enemy_in_range` 及目标校验里调用 `is_hidden_from(viewer)`，当与格温中心距离 > `shroud_radius` 时跳过她。
  - 弹体侧：发射前再次校验可见性；弹体飞行中若格温开圈且来源仍在圈外，立即销毁。
    攻击者死亡时使用最后有效位置判定；来源进入圈内则仍可正常命中。
  - 伤害侧：`_is_shroud_blocked` 继续作为最终兜底，被拦截的攻击不会造成伤害或击退。
- **克制与数值**：580 血已含机制折扣；圈内近战仍是主要弱点，逼进身位就能击中她。

## 五、新卡设计指引

1. **费用-强度曲线**（粗略）：2 费 ≈ 230 血+38 攻；3 费 ≈ 400 血+55 攻；4 费 ≈ 600 血+68 攻；5 费 ≈ 1000 血+88 攻。有特殊机制（对空/范围/召唤）就相应扣数值。
2. **DPS 参考**：伤害 ÷ 攻速 ≈ 每秒输出。近战 60-80，远程 45-60，避免全面碾压的数值怪。
3. **加卡步骤**：
   - 在 `CardDB.all()` 加一个条目（id 用英文小写）
   - 普通单位只需填数值；新机制（新法术/新行为）需要对应代码支持
   - 手牌 UI 会自动出现新卡（按字典顺序）
4. **克制关系检查**：新卡应该能被现有某张卡有效反制（如空中单位怕对空远程）。

## 六、Agent 实施与验收流程

新增卡牌时按下面的顺序执行，不要只改一行数据后直接交付：

### 1. 先分类，再决定改动范围

- 普通 `unit`：优先只新增 `CardDB.all()` 条目；通用 `_spawn_unit()` 会负责生成、部署、碰撞、寻敌和联网广播。
- 普通远程单位：在已有单位字段上增加 `projectile_speed` 和表现配置；伤害必须由主机弹体抵达目标后结算，详见 [`RANGED_3D_INTEGRATION.md`](RANGED_3D_INTEGRATION.md)。
- `building`：可复用已有建筑占地、寿命和导航注册；新的召唤、周期或死亡行为必须补 `Unit` / `main.gd` 的权威逻辑。
- `spell`：只写数据不会产生效果，必须在 `main.gd` 的 `_cast_spell()` 增加对应分支，并同步主机视觉事件。
- 隐身、穿透、死亡效果、眩晕/减速、位移、变身等新机制：先定义固定 tick 下的权威规则，再实现数据字段和代码，不得只在 3D 表现层模拟。

### 2. 添加并检查 CardDB 条目

1. 选择稳定的英文小写 `snake_case` `card_id`；它还会用于资源目录、卡面文件名、网络消息和测试查找键。
2. 在 `CardDB.all()` 中添加字段。普通单位的最小字段形状见 [`docs/AGENT_WORKFLOW.md`](AGENT_WORKFLOW.md)，数值仍以本文件的曲线和现有卡为参考。
3. `selectable` 默认为 `true`。纯系统单位才显式关闭，否则不会出现在选卡界面、随机卡组和 AI 候选中。
4. 确认新字段有代码读取方。`CardDB` 中没有消费者的字段不是已实现机制。
5. 不为普通角色在 `main.gd`、`unit.gd` 或表现脚本里增加角色名分支；只有新机制无法由现有字段表达时才扩展通用逻辑。

### 3. 需要代码时保持权威入口一致

- 玩家、AI 和联机请求都经过 `_deploy_card()` 的 0.5 秒权威延迟；不要在客户端直接生成单位或结算法术。
- 新单位、建筑和召唤物统一经过 `_spawn_unit()`，这样才会获得 `combatants`、建筑占地和主机生成 RPC。
- 新法术统一经过 `_cast_spell()`，范围命中使用目标体积相交，并由主机广播必要的表现事件。
- 攻击统一走 `launch_attack()` / `_resolve_attack_hit()`；远程不能在发射时扣血，动画回调不能调用 `take_damage()`。

### 4. 回归与交付

至少完成以下检查：

```bash
Godot --headless --path . --script tests/mechanics_check.gd
git diff --check
```

新机制应在 `tests/mechanics_check.gd` 增加明确命名的最小测试，覆盖生成/部署、目标或范围、伤害时刻、死亡或状态结束；远程卡还要覆盖弹体飞行和销毁。随后用 Godot F5 实际部署新卡，检查蓝红双方、建筑/塔目标和 UI 卡面。联机相关改动还要分别启动 host/join 并手动部署新卡。

提交说明必须列出新卡 ID、修改的脚本和资源、回归结果以及尚未完成的动画/卡面/特殊机制。完整的 Agent 工作流见 [`docs/AGENT_WORKFLOW.md`](AGENT_WORKFLOW.md)。
