## 原因：工具默认行为被导入流程继承

1. 本机 `/Users/czh/Tools/lol-asset-tools/bin/wwiser` 实际执行 `src/wwiser/bin/wwiser.pyz`。本次同时检查实际 pyz 与源码，`wwiser/wcli.py:61` 的 `--txtp-volume / -gv` 默认值为 `*`，即 **auto**。不显式传 `-gv=0dB` 就会开启它。
2. `wwiser/generator/txtp/wtxtp_simplifier.py:1018` 根据事件树中各层音量计算输出增益，再以相反数补偿，朝 0 dB 调整。它不是测量声音响度的实时 AGC，也不是根据 WAV 峰值做响度归一化。例如原事件路径衰减 −42 dB，会得到 +42 dB auto 补偿；这破坏了不同事件原本的相对音量。
3. auto 在生成 TXTP 时已经应用于节点音量，TXTP 中 `master volume: auto (+…dB)` 是记录。vgmstream 解码遵循这些增益，WAV 已带有抬高。**仅删掉这行注释无效**。
4. `tools/audio/import_card_audio.py:52` 起直接复用已有 `event_wav`；只在预览不存在时重新解码。它没有拒绝含 auto 的 TXTP，也没有验证预览 WAV 与新 TXTP 的一致性，随后直接复制并写“source event gain retained”。因此只把命令改成 0 dB，却复用旧缓存，仍会导入有问题的声音。
5. 下游裁剪、淡出、变速、合成及 −3/−6 dB 制作余量通常继承上游增益。“不归一化”“原版增益”历史备注只描述最后一步，不能证明上游干净。奥恩锻造文件的 manifest 就同时保留“无逐文件归一化”和带 +19 dB auto 的源 TXTP，是直接例子。

因此主要问题是 **wwiser 的试听增益默认值与项目“保留原事件增益”的要求不一致，加上导入器缺少检查及缓存失效机制**。没有证据表明是工具随机出错；也不能确定每次历史调用是否省略参数或显式选择了 auto，但现存 TXTP 明确证明它已生效。

Godot 侧核查：1096 个 WAV 导入文件全部 `edit/normalize=false`；另 1 个璐璐 OGG 使用 oggvorbisstr 导入器，没有 WAV normalize 参数。`default_bus_layout.tres` 无音频效果器，Master/SFX/Combat/UI/Voice 为 0 dB，Music 为 −6 dB。当前脚本没有添加总线增益/压缩效果器，GameAudioManager 使用事件配置的固定 volume_db 与淡入淡出；未发现随响度自动放大的实现。空间衰减、并发叠加与显式事件增益仍会改变听感，不能把所有听感差异归因于 auto。

## “原版增益”的执行基准

保留原 WEM 媒体和 Wwise 事件/动作/容器/声音层的原有增益，wwiser 主增益明确为 `-gv=0dB`。不要把所有节点都归零，也不要绕过事件层只拿裸 WEM 当作完整原事件。LoL 运行时 RTPC、空间滤波和随机条件不能由离线导出完整重现，保留所选皮肤、语言、条件、事件和随机变体，记录缺失项。

将来源基准、必要加工、项目混音分别登记。原版重建基线不继承用于抵消 auto 的文件增益和运行时补偿，也不自动继承统一制作余量。格温中心 +3 dB 等明确玩法听感调校作为独立项目配置列出，重导验收时再决定是否保留；不能冒充原版增益。

## 后续执行计划（本轮不实施）

1. **冻结范围和来源。**按本次 CSV 锁定 1096 个引用文件；冰冻路径列硬排除。记录当前音频/配置哈希与逐事件用途，原包保持只读。未引用锻造声先保留为来源证据，确认最终锻击的依赖后按素材规则归档，不无声删除。34 个全局声虽正常仍纳入来源基准清单，无差异则可保留现有成品。
2. **先修导出/导入防线。**所有事件生成明确 `-gv=0dB`；拒绝 auto TXTP，禁止默认峰值/RMS/LUFS 归一化和自动增益；从新的输出目录渲染，缓存键覆盖源包、事件/条件、TXTP 哈希、工具版本和加工参数。manifest 必须分别记录源事件增益、工具主增益、后期增益、运行时增益。增加最小检查：auto 输入被拒绝、0 dB 输入通过、旧 WAV 缓存不会被新参数复用。
3. **建立干净原声层。**从原包重新生成事件，保持变体及各层关系；先浮点解码检查削波，再按工程格式输出。不得用对现有成品统一减 dB 代替重建，也不得把已有候选 WAV 当作未经加工的原始源。9 个直取来源单独验证原文件与授权使用的裁剪，不强行套 wwiser。
4. **逐项重放加工配方。**所有裁剪/包络/时移/变速/合成均从第 3 步干净原声开始。每条记录切点、保留时长、淡入淡出曲线、速度/音高、层叠延迟、声道/采样率及输出增益。普通死亡遵循前 1 秒保持、后 0.5 秒线性淡出，总长最多 1.5 秒；完整建筑摧毁与既有特例保留。多层先各自还原原版增益，再按原时序混合，不对合成结果自动归一化。若超量程，记录并处理具体层关系，不能偷偷新增补偿。
5. **分批重导与播放补偿复核。**优先虚空鱼、图奇、蛮王、赛恩等大幅残留及部署/死亡语音，然后其余卡牌、法术和加工特例；73 个已补偿文件必须一起核对旧补偿，避免声音变得过小。保留卡牌事件路由、命中时机、循环停止、阵营/形态关系；不通过修改机制配合声音。
6. **验证后接入。**先素材展台对比干净源与加工成品，再在素材库 stage 副本联调，逐批同步最终文件及 manifest。检查全时长削波/截断/静音、相关性与幅度、事件增益、并发和生命周期；运行核心 mechanics 与项目 audit，实际对战试听双方、不同距离、并发、死亡/清场、塔与水晶终局。冰冻哈希必须不变。每批记录差异与可回退文件，全部通过才声称完成重导。
