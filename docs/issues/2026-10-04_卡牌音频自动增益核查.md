# 卡牌音频自动增益核查（2026-10-04）

> 2026-10-04 执行更新：已按原库重导并清除旧增益补偿，见[执行交付](../deliveries/2026-10-04_原版增益音频重导.md)。以下为执行前核查快照，数字和哈希不代表当前成品。

状态：**核查完成，残留音频尚未批量修复**。来源：用户反馈“哪些已有卡牌的音效还被抬高”。本轮只读取音频、配置和来源，新增核查报告；不覆盖上轮库奇修改。

## 结论

不是所有声音都被抬高。扫描当前CardDB全部56个定义，按实际PresentationConfig解析双方和形态，覆盖1063个唯一音频文件、2417个配置引用；包括法术、召唤物、编队成员及部署/死亡语音。未把候选、退役素材、舞台副本和未引用音频算入问题。

- **486个文件**通过波形比对确认，仍有自动增益造成的净抬高。
- **3个加工/合成文件**的上游仍含auto，单独列出，不冒充直接波形净值。
- **73个文件**虽能追到auto源记录，但当前成品/播放已抵消，或净值低于原事件。
- **476个文件**经波形核对未发现auto残留；另有9个变速/合成文件的组成源未使用auto、10个LCU直取/用户提供资源不经此导出链。
- **6个文件**有项目显式正增益，属于格温中心命中调校，不是auto。

净增益为**源TXTP的auto补偿 + 当前成品相对该TXTP的实测增益 + 该事件实际播放增益**，相对于不启用auto的静态源事件。采用0.5 dB容差；同文件有多处配置时，存在正增益用途才记入问题。表中不是LUFS、不是玩家听感倍数，也不是LoL完整实时混音的测量。Godot Master/SFX/Combat/Voice默认总线均0 dB；不把正的播放参数直接判定为异常，也不把−6 dB制作余量视为已抵消+20 dB的auto。

## 优先处理

- **虚空鱼**：普攻起手、命中为`+42 −6 −7 ≈ +29 dB`，两条死亡声为`+34 +0 −5 ≈ +29 dB`。出生声虽auto +20，运行时−23，净−3 dB，排除在残留清单之外。
- **图奇、蛮族之王、赛恩**：存在较大的残留，详见逐卡表；不能一律给整张卡减同一个数。
- **训练木桩**：15个战斗音效约+10～18 dB；**腐蚀**约+12 dB；**凝滞**约+5～17 dB；**电击**约+8 dB；**大型电击**约+3 dB。
- **库奇**：上轮修正的15个普攻/技能SFX经波形复核已恢复静态事件增益；本轮查出上轮未动的两条部署语音约+16/+17 dB、三条死亡语音约+16 dB。LCU“王牌飞行员”直取语音不属于事件auto问题。
- **已抵消的旧auto记录**：艾希、盖伦、剑圣、赏金猎人、皮克斯等有源记录auto，但当前文件已抵消其增益。详见CSV；这些卡的部分部署语音仍需另查表，不能整卡标成“全正常”。
- **有意的播放增益**：格温6个Q命中素材在中心命中事件配置+3 dB，源TXTP没有auto，列为项目调校，不混入自动增益问题。

## 加工文件与判断边界

3个上游仍含auto的加工文件：

| 文件 | 证据与结论 |
| --- | --- |
| `ornn/forge_final_strike.wav` | 从锻造原片3.5秒之后裁取，继承源auto +19 dB、制作−3 dB，事件−7 dB；按链路估计约+9 dB。与原片开头直接比对无意义。 |
| `pantheon/pantheon_r_arrival_original.wav` | 六层来源分别含+11～20 dB auto，合成组增益−4.79736 dB；每层约仍+6.2～15.2 dB，不给整个混合声单一净值。 |
| `sion/death_sfx.wav` | 源auto +19 dB，先裁切再保音高压缩并淡出；源链确认有残留，未把变速后的峰值/相关性当统一增益测量。 |

另外9个加工文件是冰鸟重生/暴风雪循环、格温4个Q合成、太阳圆盘出生及2个死亡片段；其上游未使用auto，处理记录分别为变速/裁切/不归一化混合。本轮未对这些变速合成声做完整实时混音等效证明。

编队卡近战兵小队、远程兵小队、小兵分队、炮车部队、攻城部队、重装部队复用对应成员定义，成员已全部纳入；镜像不配置独立音频，生成的单位复用原卡。世界塔、水晶、播报、音乐和UI不属于本轮“已有卡牌”范围。

## 复核方式与证据

1. Godot 4.7.1读取已编译CardDB，使用实际`PresentationConfig.audio_for()`解析阵营、形态与覆盖，不用正则猜最终卡牌配置。
2. 查遍assets来源清单，将记录SHA256与当前文件匹配；沿本地归档和外部只读工具源定位TXTP，检查`master volume: auto`数值。
3. 对1044个有直接候选源的文件重新解码浮点参考；追加库奇死亡声定位、天使70ms延迟对齐后，**1041个文件**在至少100ms有效窗口与当前成品相关系数≥0.995。使用开头1秒、8kHz单声道统一分析，在线性有效窗口估计幅度比；不拿文件峰值相近当“响度已还原”。衰减、死亡尾部淡出、时间压缩和混合不混为一谈。
4. 剩余22个为上述3个含auto的加工声、9个无auto的加工声、10个直取/用户提供源，逐项按来源链归类，未伪造直接波形比对成功。
5. 来源有auto且文件SHA相符仍不足以认定当前净增益，必须检查是否已补偿。`processing: original gain/no normalization`只是历史备注；本次发现多处这类备注遗漏了wwiser上游auto，不能继续单独依赖它。
