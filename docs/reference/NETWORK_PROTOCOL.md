## 协议96：独立服务器与双客户端

运行拓扑为一个 `--mode=server` 独立进程和两个 `--mode=join` 客户端；首期一进程一局，本地验证，不提供断线续接。服务器只推进20Hz模拟，不建立玩家UI、模型池或音频管理器。单机与工作台复用BattleSimulation固定阶段。

MatchSession保存match身份（session_id）、玩家身份（player_id）、阵营和连接peer_id。玩家身份独立于连接，首期断线结束，不实现身份重新绑定。等待两个合法卡组后加载；服务器规则实体与两个客户端资源都就绪才进入RUNNING。准备超时30秒；等待第二玩家/卡组同样有30秒期限。第三个连接被拒绝。正常终局两端离开后服务器重建会话；准备失败或局中断线发送中止后重建，生成新的会话身份。

`_rpc_offer`携带会话、协议、指纹及分配阵营。两端分别提交卡组，`_rpc_start`提供对方卡组与技能选择供资源准备和公开技能表现使用；`_rpc_running`仅下发接收方手牌及牌序。两端输入均发送给服务器peer 1，客户端不能提交阵营或目标执行Tick，服务器由连接确定阵营并约束input_tick后排程。

普通快照和可靠终局中的金币、card_growth均按接收方投影；出牌回执包含本方手牌、牌序和镜像历史，仅发送给请求者。实体出生/死亡、动作、特效与声音通知发送给两个已绑定客户端。当前隐身仍是双方可见的虚化，未改变原有信息可见性规则。载荷项数不变；旧协议拒绝握手。


## 协议97：统一命令缓冲与表现时间轴

出牌（包括单位、建筑、法术、镜像）和主动技能统一使用CommandSchedule.BUFFER_TICKS=10，即0.5秒；服务器由input_tick确定目标Tick。迟到到期、明显未来及旧请求在付款前拒绝，不额外追加半秒，不自动重试。费用、卡牌轮换及技能取消/退款沿用原规则；技能执行时重新检查资格和控制，存活但无法开始则退原费用，死亡/终局关闭收据。单机玩家和AI仍走同一排程；工作台显式即时预览保持独立。

服务器接受操作后，可靠`_rpc_command_scheduled(epoch, command)`立即发给两端。命令含唯一id、kind(card/skill)、team、card_id、ability_id、pos、input_tick、execute_tick；不含金币、手牌或牌序。NetworkCommandState检查字段、固定10Tick间隔并按ID去重，保存待执行信息。客户端只准备资源/显示本方等待状态，不根据通知生成实体或结算技能。对方操作不提前显示在UI；网络消息本身包含对方意图，不提供抵抗修改版客户端的意图保密。

命令执行或取消后发布`_rpc_command_finished(epoch,id,outcome)`（executed/cancelled），按权威Tick播放；结束与取消幂等移除准备记录。已接受技能不再通过立即拒绝回执提前解锁按钮。终局/断线丢弃所有命令与播放队列，不等待缓冲，也不把旧局通知用于新局。

NetworkClock在独立unreliable通道2发送带会话及探测序号的往返样本；服务器校验已绑定玩家并限每200ms一次。客户端以最近8个样本的最低RTT估计时钟偏移，拒绝未知、重复和超过2秒的样本；首次每250ms尝试，成功后每秒采样。返回模拟Tick与不足一Tick的相位，不把积压当已执行时间。RTT/2不能准确识别不对称链路，时间戳仍是受服务器窗口限制的客户端估计，不是可信点击证明。

公共出生、死亡、动作、技能、范围、声音事件通过带epoch、tick、白名单method和args的战斗信封传输；可靠事件使用通道0，原有可丢短音使用unreliable通道1。客户端NetworkPlayback将快照和事件放在同一时间轴，落后估计服务器2Tick（100ms）；同Tick保留事件顺序并最后应用快照。迟到事件在下一播放帧追赶，已有实体/动作/快照屏障防止回滚。队列上限4096，溢出明确结束连接；终局可靠最终快照立即生效并清队列。法术在途进度读取相同表现Tick。原有单位位置平滑仍保留，并非完整历史快照插值重写。

命令缓冲500ms与表现缓冲100ms不同：后者不改变服务器执行Tick，但会增加视觉延迟。固定Tick量化、时钟误差、下行抖动和丢包意味着不能承诺点击后精确500ms两端同时显示。本方已确认出牌以落点圆环提示，技能按钮按目标Tick显示等待秒数；提示不能驱动任何规则。选牌/拖动/查看信息立即响应，准备/退出/断线走会话管理。


## 协议98：可见手牌投影与自适应表现

服务器/单机的CardCycle仍拥有完整八牌顺序和四张待抽队列；客户端改用ClientHandState，初始化为空，既不创建CardCycle也不临时洗牌。CardHand同样仅保存四张手牌与一个next_card，不拥有消费/补牌逻辑。

`_rpc_running(epoch,state)`与`_rpc_deploy_accepted(epoch,card_id,execute_tick,state)`只向本方发送五字段状态：version、ack、hand(四张)、next(一张)、history(镜像所需最近成功来源)。不包含queue、随机种子或对手手牌。服务器每次成功轮换增加version，ack是生成这份状态时的已处理玩家请求序号。客户端验证字段、卡组成员、五张不重复，拒绝旧版、重复版与请求编号倒退；历史随同一版本原子更新。拒绝出牌/技能的回执也带request_id，只清除完全对应的本地等待请求，不能把后继请求提前解锁。

洗牌使用每个CardCycle独立RandomNumberGenerator；服务器以独立随机种子创建双方牌序，Fisher–Yates洗牌并保留镜像不进首手的约束。不消耗战斗全局随机流。服务器`[CARD_ORDER]`日志记录会话、阵营、十进制字符串seed、备战deck与初始opening；仅在服务器日志中，不发客户端。相同引擎和洗牌规则版本下可从种子复现。单机也用相同洗牌核心；当前没有增加存档或重连功能。

ClientInputState在发送请求时立即显示本方落点等待提示或按钮pending；在收到确认前不扣费、不换牌、不建立战斗对象。接受后转为服务器排程提示，拒绝后撤下，对局结束清空。客户端以卡牌ID+单调request_id关联回执。

NetworkPlayback默认100ms，根据时钟RTT/抖动与事件/快照到达时差动态调整到50–200ms：最近32个观测的90分位加一Tick余量，抖动增大快速增加、稳定后缓慢降低。播放Tick只前进，增大缓冲可能短暂保持上一帧，不回滚战斗。变化只在客户端表现层，10Tick操作缓冲和20Hz权威模拟不变。

梦魇单次效果盾复用U_ACTIVE_BUFF_ACTIVE表现存续；Delivery只属于权威执行，不加入快照。协议99包含该规则与新卡内容；客户端不自行判断抵挡。

爆破酒桶复用可靠在途发射/抵达载荷；真实命中后用卡牌表现事件 explosive_cask / spell:hit 传递固定受击位置。客户端仅播放 Mis、End、Tar，不重新查询伤害对象。

镜像成功释放复用可靠 `_rpc_card_event`，载荷为 `card_id=mirror`、`cue=spell:cast` 及释放位置、施放队伍；双方均播放0.5秒镜面提示，不新增协议字段，不影响权威复制结果。

协议100新增公开释放提示：复用可靠 `_rpc_card_event` 的 `cue=cast:notice`；card_id为释放卡牌/主动技能来源，form字段在此cue下为技能候选下标，team为施放队伍，pos不使用。按事件ID去重、会话校验和战场播放时间轴显示，服务器不创建表现节点。
