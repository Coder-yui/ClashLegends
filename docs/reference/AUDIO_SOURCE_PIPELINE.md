# 音频来源、转换与记录

已有可用 WAV 时不必重新解包，先核对来源清单。主流程见 [音频接入](../AUDIO_INTEGRATION.md)。

## 识别来源

| 来源 | 含义 |
| --- | --- |
| 事件渲染预览 | 可能是完整事件，仍须核对条件和层叠 |
| 按事件归类的组成声音 | 不保证每个文件能单独代表完整事件 |
| 数字媒体 ID 的原始 WAV | 只是媒体解码，ID 不等于动作名 |

待开发队列选定素材要迁移并记录源已移除；外部共享原始库保持只读。待转换源包应保留明确归档位置，不能因为导出了 WAV 就删掉唯一源包。

## 只有 WAD / BNK 时

1. 在项目外工作目录定位英雄、皮肤、语言及共享初始化包。
2. 解析皮肤事件名与 Events/Audio/Init 层级；恢复名字时核对 ShortID。
3. 沿事件、动作、容器、声音到媒体 ID 解析，保留随机、层叠和条件。缺节点、缺媒体必须记录。
4. 用事件描述和解码工具导出 WAV；提取媒体不等于恢复整个事件。FFmpeg 不保证能直接识别所有 WEM 编码。
5. 保留工具版本、参数、事件描述、媒体映射和失败原因。

本机工具说明在 `/Users/czh/Tools/lol-asset-tools/README.md`；执行前检查文件存在和工具帮助。既有逐英雄脚本可能固定本机路径与英雄，不当作通用解包器直接重跑。

恢复到的是事件名，不一定是工程原 WAV 名。未知条件保留 ID，不猜材质用途；停止事件可能没有独立 WAV。离线渲染不代表完整复现实时滤波、空间参数和随机音高。

## 成品与清单

WAV 使用可辨识事件名与变体编号，避免命名碰撞。manifest 至少记录文件、原事件和来源预览；已知时补事件/媒体 ID、语言、皮肤、工具参数、转换前后时长和哈希。候选媒体集合不能冒充逐变体的精确组成。

检查非静音、有效时长、声道、采样率与爆音。原有增益优先保留，0 dB 不等于同响度。替换前确认新资源可用，只处理明确退役的文件，不清空其他素材。

普通单位死亡声默认加工为最多 1.5 秒：源声超过上限时，前 1 秒不变，后 0.5 秒线性淡出；更短素材保留。共用工具为 `tools/audio/death_audio_envelope.py`。**建筑完整摧毁声和已明确调校的个别事件不套用这个默认值**，按当前 manifest 处理，不能重导时抹去特例。

声音加工不改变动画或战斗时长；清单写入的是实际处理结果，来源库保持原样。
