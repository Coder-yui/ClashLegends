# 兵种部署与出场动画约定

本文是后续 Agent 接入角色素材时必须检查的部署规范。战斗规则由 `Unit` 和主机固定
tick 驱动，动画只负责表现，不能反向决定单位何时可行动、何时受伤或技能何时生效。

## 两段部署时序

所有手牌（兵种、建筑、法术）在主机确认、扣费后，统一等待 `0.5` 秒再真正生效。
这个窗口用于吸收客户端到主机的网络延迟：兵种和建筑在窗口结束时生成，法术在窗口
结束时结算。墓碑召唤的小鬼等非手牌生成物不经过这段延迟。

兵种生成后立刻进入自己的 `deploy_time`，默认 `1.0` 秒。部署期间：

- 不能索敌、移动或攻击；
- 已经拥有实体碰撞，会与其他单位发生推挤；
- 可以被敌方单位和塔索敌，也可以被普攻、弹体、范围伤害和法术命中；
- 受伤、死亡和状态效果均按权威模拟正常结算。

因此“0.5 秒卡牌延迟”和“1 秒兵种部署”是先后两段时间，不能合并成一个读条。

水晶自动兵线是例外：它们不经过玩家卡牌延迟，也不进入 `deploy_time` 部署读条。每个兵线
单位在生成当帧就可以移动、索敌和攻击；同一规则通过主机生成 RPC 同步到客户端。

## 部署动画选片

接入一个新角色时，Agent 必须实际检查 GLB 的 `AnimationPlayer`，再在
`CardDB.visual_animations.deploy` 中显式填写动画名。选择顺序为：

1. 优先使用 `respawn` / `Respawn` 类出场动画；
2. 没有时使用 `recall-winddown` / `Recall_Winddown` 类回城收尾动画；
3. 两者都没有时使用该角色的 `idle` 动画兜底。

动画名区分大小写，必须填写素材中实际存在的名称，不要在运行时猜测近似名称。普通
单段部署动画会缩放到 `deploy_time`。如果一个角色的部署动作由多段组成，可以给
`deploy` 配置动画数组，并用 `deploy_durations` 显式给出每段时长；各段总时长必须与
`deploy_time` 一致。

## 赵信特例

赵信的 `deploy_time` 为 `1.5` 秒，部署序列是：

```text
Spell4 → Spell4_To_Idle
```

单位生成的第一帧就播放 `Spell4` 并由主机立即结算一次横扫千军击退，然后播放
`Spell4_To_Idle` 收枪。整段 1.5 秒就是他的部署阶段，不再额外叠加普通 1 秒部署或
部署后演出时间。赵信在此期间仍可碰撞、被索敌和受伤。

## 验收

- 普通单位生成后约 1 秒内没有自主移动或攻击，但敌方能锁定并伤害它；
- 两个重叠生成的部署中单位会发生碰撞分离；
- 赵信生成当帧触发横扫，1.5 秒后才恢复行动；
- 兵种、建筑和法术都必须在出牌确认约 0.5 秒后才出现或生效；
- 单机、主机和客户端的生效顺序一致；
- 运行 `tests/mechanics_check.gd`，并在实际渲染中检查部署动画没有被 Idle 提前打断。
