## 2. 被动

### 四段双拳连招

- 命中后到下一次命中的间隔数组为 `[0.60, 1.40, 0.60, 1.40]`，形成“两拳、停顿、两拳、停顿”的循环。
- 没有攻击范围内的下一目标时，取消权威后摇并追击。被动 Hit 退出时用专用转跑，已经进入 Into_Idle 后退出则直接混合到跑步，避免收完拳后又重播伸拳姿势。
- 有目标时按上述命中间隔继续：Hit 和收势允许下一拳打断，不要求为了播完所有素材延迟命中。技能/离圈取消未命中的拳后，恢复的动作、伤害倍率与间隔仍对齐尚未结算的拳段；表现序号保持递增，允许跳号。
- 四段伤害倍率为 `[1.0, 1.5, 1.0, 1.5]`，对应 `72 / 108 / 72 / 108` 点基础伤害。

### 豪意

- 豪意上限 `200`；每次挥拳获得 `20`，承受实际生命伤害按 `1.0` 倍获得资源。被护盾吸收的部分不算生命伤害。
- 只有主动槽实际携带“蓄意轰拳”时才显示和积攒豪意；受击或挥拳会刷新 1.0 s 脱战计时，计时结束后按 100/s 衰减；主动技能 Cast Start 读取当前豪意并清空资源。
- 资源条以连续进度显示，未满时为白色，满层为黄色 `Color(1.0, 0.82, 0.24, 0.96)`。

## 3. 主动技能

**蓄意轰拳**（`kind = frontal`，`shape = trapezoid`）

- 当前主动技能数值：消耗 `2` 金币；每个腕豪最多使用 `1` 次；每次使用后冷却 `8.0 s`。
- 锁定移动、普通攻击和朝向，在前方长度 `155` 的梯形区域结算；近端宽 `54`，远端宽 `170`，只影响地面目标。
- 基础伤害 `130`，随豪意从 `1.0x` 线性提升到满豪意 `2.0x`，所以外圈最高 `260` 点。
- 梯形中央比例 `0.34`，中央伤害倍率 `1.5`；满豪意中央最高 `390` 点。
- 护盾按豪意比例从 `0` 到 `300` 点映射，Cast Start 立即获得，持续 `2.0 s` 并线性衰减。
- 护盾剩余值与生命条处于同一行，接在当前生命值段之后以白色条显示；护盾即使没有受到攻击也会按时间减少，伤害结算时优先扣除护盾。
- 普通资源 `impact_delay = 0.8 s`、`cast_duration = 1.4 s`；施法期间全锁。
- 满豪意使用 `Spell2_Strong`，`impact_delay = 0.8 s`，与普通 W 使用相同伤害时刻；施法总时长仍为 1.4 s。伤害由固定模拟结算，不由动画回调触发。

## 4. 使用的动画

- 场景：`res://assets/units/sett/sett_view.tscn`；`visual_forward_yaw = 0`。
- 部署 / 待机 / 移动：`Respawn` / `Idle_Base` / `Run_Base`。部署取 Respawn 前 1 秒原速播放，之后由权威状态切到攻击 / 移动。Respawn→Attack1/2_Start 按原表 L6617/L6812 使用 0.1 秒混合；未找到 Respawn→当前 Run 节点的专门边，保留项目通用移动混合。
- 四段出手：`Attack1_Start`、`Attack1_Passive_Start`、`Attack2_Start`、`Attack2_Passive_Start`。
- 四段 Hit：`Attack1_Hit`、`Sett_Attack1_Passive_anm`、`Attack2_Hit`、`Sett_Attack2_Passive_anm`；`attack_reference_interval = 1.0`，参考间隔下按原速播放，不再将两段被动 Hit 全段压到 0.32 秒。
- Start 按权威前摇窗口播放；Start→Hit 的逐边混合依次为 `0.02 / 0.04 / 0 / 0`；两套被动拳恢复原表值，用户复查确认首尾姿态连续，快速段来自 Hit 素材内部。两套被动 Hit→Into_Idle 仍使用原表零混合。其他未核验的边保留通用混合。
- 被动段收势：第二、第四段使用 `Attack1_Passive_Into_Idle`、`Attack2_Passive_Into_Idle`；仅在 Hit 完成且尚未被新动作替换时进入。连续攻击通常会在 Hit 尾部被下一拳接管。
- 攻击后移动：第一、第三拳选 `Run_Passive`；第二、第四拳选 `Run_Base`。`Sett_Passive_INTO_Run_anm` 只在实际来源为两段被动 Hit 时使用，不再仅按拳段索引插入。
- 普通 W：`Sett_spell2_anm`，前 0.8 秒原速播放，剩余约 0.767 秒压到 0.6 秒，总计 1.4 秒，入口混合 0.10 秒；转跑使用 `Sett_Spell2_INTO_Run_anm` 的 0.4 秒起点（本项目完整 W 已起身，避免重播低姿态），入口混合 0.10 秒。
- 满豪意 W：`Spell2_Strong`，前 0.8 秒原速播放，剩余约 0.367 秒拉长到 0.6 秒，总计 1.4 秒，入口混合 0.04 秒；转跑使用同一 ToRun 的开头，入口混合 0.10 秒。
- W 结束时若下一拳已开始则直接衔接攻击；静止时分别接 `Spell2_Into_Idle` / `Spell2_Strong_Into_Idle`，再回 `Idle_Base`。收尾可被攻击、移动、技能和死亡打断，不增加权威施法锁定时间。
- 死亡：`Death` 取源时间 0–1.7 秒，以 2.125× 播放到 0.8 秒后移除模型；省略倒地后细微变化，权威单位仍立即死亡。

## 5. 攻速调整与验证（2026-09-12）

基础数值只改 `scripts/data/cards/sett.gd` 的 `BASE_ATTACK_INTERVAL`：当前 1.0 秒，前摇为其 0.3 倍，命中间隔按 0.6 / 1.4 倍交替，面板显示完整循环平均值。旧循环平均间隔为 0.665 秒；本次平均出拳频率降低约 33.5%，单拳伤害、生命与技能伤害数值未改。普通与强化 W 的 impact 均为 0.8 秒；撤销此前为匹配强化素材而加入的 0.95 秒覆盖。动画对齐应在表现层处理，不能推迟满豪意伤害。

局内攻速使用通用 `apply_active_buff(..., attack_speed_multiplier)` 或 `apply_attack_speed_slow(...)`。权威前摇、冷却、后摇与表现进度按同一个有效倍率变化；中途切换倍率保留进度，不重播拳段。Hit/Recover 还按基础间隔相对 `attack_reference_interval` 的比例适配。技能、部署、移动、死亡和音高不会被普攻 Buff 一起加速。

已跑统一 mechanics：包含 0.5× / 1× / 2× / 4× 连续六次真实命中、Buff 生效/到期、减攻速恢复、冻结、基础数值变动、晚到进度 seek、技能取消右拳后的拳段一致性，以及新字段和素材契约。固定 20Hz 的时间分辨率仍为 0.05 秒；不宣称任意极端攻速都能保留完整每一帧动画。

原始依据见 [修改前对照](../research/sett_animation_comparison.md)和[证据摘录](../research/sett_animation_evidence.json)。实际渲染复查工具：`Godot --path . --fixed-fps 30 --script tools/demos/sett_animation_preview.gd`，输出 `/tmp/clash-sett-animation/` 的连续帧及动作日志，覆盖双方阵营、变速、冻结、普通/强化 W 各出口与死亡。此工具的近景相机只观察同一战场，不驱动模拟。

前轮验收（死亡裁剪调整前）：统一机制检查 516 项通过；独立主机 / 客户端运行验证攻速倍率与动作序号同步；43 秒实际渲染连续帧已目视检查，包含 W 转跑、接普攻、两种静止收尾和原速死亡。演示视频输出为 `/tmp/clash-sett-animation/sett-animation-review.mp4`（无音轨；不作为音频试听验收）。

## 音频接入（2026-09-11）

已接入的动作、原始事件与文件见 [音频映射](../../../../assets/audio/units/sett/README.md)。完整动作对照、来源、自动验证及待人工试听项见 [全卡音频对照](../../../AUDIO_CARD_MAP.md)。本轮不改变既有 2D / 3D / 卡面状态；音频来自外部 LoL 原始库只读提取，未移动待开发队列素材。

### 2026-09-12 出拳对齐与混合适配

按用户对原始片段的观察，两种 W 都在源时间 0.8 秒完成出拳；权威 impact 统一设为 0.8 秒，cast_duration 保持 1.4 秒。用现有 visual_actions 的重复 animation + clip_ranges + durations 实现连续分段：前段 [0, 0.8] 播放 0.8 秒，后段 [0.8, 源片段结尾] 播放 0.6 秒；sequence_blend 为 0，交界是同一片段的同一姿态，避免自混合拖动命中点。未新增角色专用播放器逻辑。

两套被动 Start→Hit 的混合最终恢复为原表 0.04 / 0 秒。原始图可提供顺序、资源映射和逐边混合参数；仅凭这些数据不能确认 Riot 播放器的求值、过渡采样和运行时切换条件完全一致。本项目明确区分原始依据与观感适配。

本次验证：518 项机制检查通过，含两资源分支相同 0.8 秒命中延迟、两套被动混合值、W 前段原速与后段 / 晚到进度映射。43 秒实际渲染已检查，视频 `/tmp/clash-sett-animation/sett-w-aligned-review.mp4`（无声）。

### 本轮收尾

部署增加原始 `Play_sfx_Sett_Respawn3D_buffactivate` 的前 1 秒声音（尾端 50ms 淡出），由通用 `deploy:start` 在生成时播放一次；重绑和晚到快照不补播。普攻出手 / 命中依旧跟随拳段序号与真实结算，W 保留两种 0.8 秒命中、1.4 秒施法与分段动画，命中声随真实伤害派发。死亡叫声仍在死亡时触发并自然结束，不随 2.125× 动画变调，也不在模型移除时硬切断。

最终收尾验证：519 项机制检查通过；主机和客户端各记录一次 deploy:start，连接与运行无脚本错误；部署 / 裁剪死亡完成双阵营实际渲染检查。`sett_animation_preview.gd -- --lifecycle-only` 可生成 6 秒专项复查（输出固定帧，截图等待时不额外推进模拟）。实际音频录音约 11.1 秒，非静音且未见满幅削波，部署 / 普攻 / 两种 W / 冻结恢复 / 死亡事件均出现；主观听感仍需人工试听，不以日志代替听感验收。

2026-09-13 全面音频复核：[逐项结果与验证](../research/hero_audio_completeness_audit.md)。当前可明确对应的普攻/被动/已接技能缺项已补入；不引入原版未实现技能或未经确认的条件音。
