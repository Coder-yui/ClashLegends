## 冰鸟听感与播放组织

后续用户逐帧校准已替代下述首次修复数值：当前攻击间隔 1.7 秒，swing 0.60 秒、出弹 0.675 秒、lead 0.075 秒，见 [冰鸟当次校准记录](../cards/anivia.md#挥翼节点调整2026-09-13)。下文保留首次诊断记录。

实战一直是事件驱动的并行混音：攻击表现序号开始出手声，权威弹体创建立即播放发射声，碰撞伤害成功播放命中声；不同 AudioStreamPlayer2D 汇入 Combat 总线。没有等待 swing.finished 才 launch 的串行队列。原始资源也分为 OnCast / OnMissileLaunch / OnHit 事件，支持按游戏事件分别触发的解释；这不等于取得了 Riot 播放器/服务器完整实现。

原出手 WAV 长 0.7745 秒，但主能量集中在前约 0.3 秒：50 ms RMS 窗口在约 0.10–0.15 秒为 -26.8 dBFS，到 0.50 秒后低于约 -54 dBFS。发射 WAV 起音最初约 0.10 秒也较弱。项目 first_hit=0.58 秒，出手从 0 开始会有明显弱声段；不是因为播放器等到 0.7745 秒。

新增可选 `audio.attack_swing_lead_time=0.32`，将冰鸟 swing 安排在基础前摇约 0.26 秒处，继续使用原始 WAV、音高和增益。单位的归一攻击进度驱动，随攻速变化缩放；冻结/眩晕等待，技能/移动取消不补播。未更改 first_hit、攻速、弹体速度、动画或伤害。它是项目较长前摇的声音适配，不是原 LoL 的已确认常数。

真实 Godot 录音：`/tmp/anivia-audio-after.wav`。观测到连续三次 swing→launch 间隔约 0.30 秒；launch 触发时 swing 播放位置约 0.28–0.29 / 0.7745 秒，仍在播放。命中独立触发。说明混音重叠已生效；录音不代替人工听感评价。

旧 preview_attack 辅助 API 只排出手和命中，现补入发射/额外出弹层，并以卡牌射程估算示例飞行时间；它不参与实战。工作台逐 WAV 试听仍只用于核对单份素材。

## 生命周期与验证

- 命中、中心附加层、回血只在真实效果成功后派发；空挥/空放/满血无实际回复不伪造成功音。
- 落地声是星体撞地事件，即使空放也响；冲击波命中通过保存的 card_id/form 来源派发，不依赖施法者仍存在。
- 缠流独立持有音层，进出状态去重；控制暂停、单位释放/死亡/换场清理；未做样本级无缝循环承诺。
- 化蛋、孵化和部署命中沿用可靠卡牌事件 ID 路径，避免原单位先销毁时丢失资源来源；不会反向触发复生/伤害。
- 全部 16 个定义所引用 WAV 的路径、非静音与已有 SHA-256 检查通过。新增源媒体/事件信息进入各 manifest。
- 13 张含英雄/炮台的工作台实战录音和截图完成。日志确认新增普通/强化发射、nova/拍击/激光/星落/冲击波/中心命中事件。
- 本机 host/join 复核了普通/强化发射、拍击、分段中心命中、星体落地、化蛋与孵化的客户端重放。未声称广域网听感或网络抖动验收。
- 完整 mechanics 回归 559 项全部通过；`git diff --check` 通过。13 份实战录音的采样峰值检查未发现削波；所有音轨主观听感仍待人工试听。

原始事件组织的解释另参考 [Wwise 官方 PostEvent 接口](https://github.com/audiokinetic/WwiseIncludes/blob/master/SDK/include/AK/SoundEngine/Common/AkSoundEngine.h)：事件异步提交至声音引擎，并返回播放 ID。这支持按游戏事件独立提交声音的播放模型，但不能证明 LoL 的具体触发时间、混音参数或内部脚本。本文对项目实战并行播放的结论来自本地代码和运行记录，对 LoL 的描述仅限原素材事件表与该接口能支持的范围。
