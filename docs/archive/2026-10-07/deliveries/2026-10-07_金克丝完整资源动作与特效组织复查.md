## 1. 新增资源确实有用，但脚本文件不等于完整实现

本地版本元数据为 `16.19.8217343`。这次检查包含新增的 Game 客户端内容、Global/DATA/Scripts 包和其他 WAD，而非只看英雄包。客户端程序中的相关名称字符串检索也未发现可直接追踪的调用证据；这不能证明原生代码中不存在实现。

在 `Scripts.wad.client` 中找到并提取了 `data/characters/jinx/` 下的 108 个文件，其中 65 个 `.luabin64`、43 个 `.preload`。只读解析，没有执行这些脚本：

| 文件 | 实际内容 | 能得出的结论 |
| --- | --- | --- |
| `charscriptjinx.luabin64` | 60 字节，只有 RETURN | 不含角色更新逻辑 |
| `jinxruncyclemanager.luabin64` | 98 字节，LOADBOOL、SETGLOBAL、RETURN | 只设置 `PersistsThroughDeath = true`，没有跑步相位管理函数 |
| `jinxq.luabin64` | 406 字节，布尔值、图标、BuffName、皮肤列表等赋值 | 不含 Q 切枪、动画替换或混合调用 |
| `jinxpassivekill.luabin64` | 205 字节，图标和 BuffName 赋值 | 不含速度线挂载调用 |

65 个文件全部没有子函数，操作码仅 LOADBOOL / LOADK / NEWTABLE / SETGLOBAL / SETLIST / RETURN。`.preload` 给出了被动标记→击杀增益/攻速/移速、Q→图标等预加载依赖，但不是事件执行或挂点代码。

因此，之前笼统说“没有脚本”的结论应修正为：**脚本资源存在，已解码的 Jinx 字节码仅保留元数据，关键调用逻辑不在这些文件中。** 不能据文件名臆测原版相位算法，也不需要再要求用户补同类本地文件。

## 2. 动作组织：身体、武器、枪口挂点分别处理

动画图有 93 个剪辑节点、561 条 `TimeBlendData` 记录，包含 Atomic、Parallel、Sequencer 等结构；并非按 ANM 文件名顺序轮播。

### Q 是身体动作与武器动作并行

| 图节点 | Default 轨身体动作 | Minigun 轨武器动作 |
| --- | --- | --- |
| `Spell1` | `minigun_spell1_weapon2.anm` | `minigun_spell1_weapon_gunonly.anm` |
| `0xc3d330cb` | `launcher_spell1_weapon2.anm` | `launcher_spell1_weapon.anm` |

`Minigun` 遮罩经原始 SKL 顺序核对，仅覆盖 13 个武器相关骨骼，包括枪管、弹鼓、握把、枪带和挂点，**不是人体上身遮罩**。这证明伸缩是独立武器层；按用户决定仍不接入该层。

动画图确实还有两张上身遮罩：脊柱权重 0.5、颈部和单侧手臂权重 1；分别被 `Spell3_Run` 和火箭形态对应节点使用，属于 E 的移动施法。Q 的身体节点未显式引用这两张遮罩，不能据此把 E 的做法认定为 Q 的原版做法。

`ConformToPath` 事件引用的遮罩覆盖两条辫子的 12 个骨骼；皮肤中的对应 rig modifier 同样列出头发。它不是腿部相位同步证据。

### 两种形态还有独立的枪口挂点状态

已通过名称哈希对应确认：

- `Minigun_To_Rlauncher`（`0x622bd465`）：`JointSnap` 将 `BUFFBONE_GLB_WEAPON_1` 对齐 `Cstm_Buffbone_Rocket_Launcher`。
- `Rlauncher_To_Minigun`（`0x2ec639bb`）：对齐 `Cstm_Buffbone_Minigun`。
- 两者使用 `jinx_buffbone_swap.anm`、专门的 `WeaponBuffbone` 遮罩；遮罩只包含 `Buffbone_Glb_Weapon_1`。皮肤默认动画中列有 `Rlauncher_To_Minigun`。
- 角色定义中的轻机枪弹体起点为 `Buffbone_Glb_Weapon_1`，火箭弹体起点直接使用 `Cstm_Buffbone_Rocket_Launcher`。

**这是发射挂点切换，不是枪管展开/枪身缩小。** 当前项目绑定 `Minigun_Barrel1` / `Rocket_Launcher_Front`，属于近似方案。后续可以独立改用原版专用挂点，不必恢复伸缩层；需验证转换后的骨骼变换、枪口位置及已有额外发射偏移，避免偏移叠加。

### 跑步与切枪应怎样处理

原版两种枪有各自的 Run 动作。当前找到的图中，没有两种基础 Run 与 Q 身体节点之间可直接解释相位续接的显式混合项；数值优先级、Flags 位也不凭字面猜测。不能把某个辫子混合的 0.1 秒当作切枪脚步混合时间。

可落地的项目方案仍是：持续的移动相位驱动腿部；切枪时上身播放身体切枪动作，腿部在旧、新形态跑姿的同一归一化相位间过渡；结束后基础播放器接回该相位。现有 `jinx_model.gd` 已做这类适配。**保留该方案，但标注为本项目实现，不声称已经逐项恢复原版算法。** 切枪时长、硬控制和攻击锁仍由权威逻辑负责。

### 六个轻机枪攻击节点不能按文件数字直接解释

图节点到文件的映射为：Attack1→attack1、Attack2→attack5、Attack3→attack3、Attack4→attack4、Attack5→attack2、Attack6→attack6。节点编号与文件编号并不相同；文件有六份，不代表必须采用六种独立人体动作。本轮未重新逐帧判断动作等价性，不推翻已选两种基础攻击的决定。待机每形态一种、不接加速跑、不接无用表情和衔接的范围也保持不变。

## 3. 特效组织：事件资源键 → 皮肤映射 → 共享粒子定义

角色/技能引用效果键，Skin0 的 `ResourceResolver` 映射为粒子对象；大量定义位于 `Jinx_Multi_Skins_*.bin`，不是全在 `skin0.bin` 内。这次重新提取四个相关共享 BIN。被动和常规 Q 共用定义的两份 BIN 与之前留存文件字节一致，说明不是换了一份素材才改变结论，而是此次重新核对了组织方式。

### 罪恶快感

| 资源 | 组成 | 用途与证据边界 |
| --- | --- | --- |
| `Jinx_Base_Passive_Buff` | 一个 Streaks 发射器；`overdrivelines_iblitz.tex` | 持续速度线；没有在此定义中写明创建时绑定哪根骨骼 |
| `Jinx_Base_Passive_Buff_OnKill` | Cloud + Flash | 独立触发闪光；不能当作速度线的发射位置来源 |

速度线原数据有 `EmitterPosition=(0,50,50)`、出生分布参数 `(50,1,30)`、后向出生速度 `(0,0,-200)`、基础寿命 0.3 秒及少量更长粒子。**发射器内部偏移不等于创建特效时的世界挂点**；还涉及创建变换、朝向和坐标转换，不能机械相加后就宣称是原版挂载。

当前 `BODY_MOUNT_OFFSET=(0,-50,-90)` 是本项目根挂载校正，源配置未出现该值。后续以躯干略后方为发射区域，朝身后发射；用原纹理、出生分布和生命周期，分别验证正面、侧面、背面、转向和停止。具体绑定与数值仍需实渲校准，不能伪称已找到原版调用。6 秒刷新、攻速叠层和移速衰减使用本项目既定规则，不能由原版粒子时钟反向驱动玩法。

### 火箭爆炸：发现当前选层偏差

| 资源 | 发射器状态 | 适配建议 |
| --- | --- | --- |
| `Jinx_Base_Q_Rocket_tar` | 15 个定义，仅 Flash、Sparks、EnergyLower 未显式禁用 | 基础命中核心从这三层出发 |
| `Jinx_Base_Q_Rocket_Tar_Unit` | Sparks、Flash；带目标尺寸缩放字段 | 目标受击层与地面范围分开，不能用目标大小决定爆炸半径 |
| `Jinx_Base_Q_Rocket_GroundAOE` | 18 个定义，11 个未显式禁用；包含地面标记、网格圈和能量层 | 是范围表现候选，按实际需要选择并验证，不能因为名称存在就假定每次普通攻击都调用 |

现有 `jinx_projectile_effect.gd` 用 `Jinx_Explosion_Flat` 和 `Jinx_Explosion_Smoke` 图集制作二维火焰/烟雾。它们对应本次版本 `Q_Rocket_tar` 中显式禁用的 `Explosion_01_Add` / `Explosion_Smoke` 层；因此现有爆炸虽然使用原版贴图，**并不是该版本原版启用层的组合**。

建议下一轮先恢复启用的命中核心，再独立制作范围层；范围主视觉按本项目 45px 溅射半径标定，保持中心与地面高度一致，不把所有层和所有资源一起叠上去。源码未提供三套资源的完整创建调用，不能把候选组合写成已确认原版播放顺序。需要在素材库 stage 副本中实际渲染，与伤害范围叠图验收后再同步。

轻机枪资源也再次确认：`Jinx_Base_Q_Minigun_Mis` 引用 `Jinx_Basic_Bullet.tex` 等纹理，其中确有共享/其他英雄命名的尾迹纹理；共享命名不能证明用了库奇子弹。当前轻机枪主体贴图来源成立，无需因外观相似替换。

## 4. 下一轮建议顺序

1. **原版专用发射挂点**：替代枪管/炮身近似挂点，核对朝向、缩放和额外偏移；不涉及武器伸缩。
2. **火箭爆炸选层**：优先纠正使用禁用层的偏差，拆分命中核心、受击层和范围层，在 45px 范围上实际验收。
3. **被动挂载校准**：保留原粒子素材和分布，明确使用项目躯干后侧挂载适配；检验朝向变化与刷新，不把未找到的原版挂点写成事实。
4. **动作整理**：保留共用步态相位与两种基础攻击，按原图区分身体、武器和挂点职责；已暂缓的枪管展开/枪身缩小继续暂缓。
