# 交付合同：统一操作缓冲与客户端时间轴

- **需求 / 来源**：用户对话；所有影响战局的玩家操作采用0.5秒网络缓冲，服务器执行完整对局、本地负责表现，核查遗漏并实现。
- **完成结果**：协议97。出牌与主动技能共用CommandSchedule的10Tick常量；加入服务器公开排程/完成身份、客户端时钟采样、快照与战斗事件的100ms统一播放缓冲、本方出牌等待圆环和技能倒计时。保留单机/AI共享核心、断线结束、工作台显式即时预览。
- **验证**：基线`6998fd64`，保留前序未提交工作；Godot `4.7.1.stable.official.a13da4feb`。最终`python3 tools/dev.py verify --network-boundaries`全部通过：63套件、10310断言、三进程终态/私有状态一致及10个网络边界用例。[完整验证结果](../../../../ClashLegends-开发素材库/04-中间产物/构建与验证/verification/20261007-160206-863987/result.json)。
- **查看方式**：项目根运行`bash tools/run_local_multiplayer.sh`。本方出牌接受后出现等待圆环，技能按钮显示等待秒数；对手不显示提前操作提示。单机入口仍直接与AI对战。

## 操作边界与建议

| 操作 | 处理 |
| --- | --- |
| 单位、建筑、法术、镜像出牌 | 同一10Tick命令缓冲，服务器校验、扣费、轮换、排程 |
| 主动技能，包括免费追斩、主动变形等既有技能变体 | 同一10Tick命令缓冲；到时重新检查执行条件，沿用费用/次数/冷却及取消政策 |
| 选牌、鼠标落点预览、查看卡牌/技能信息 | 本地立即响应，不改变战斗状态 |
| 备战卡组、主动选项、资源就绪 | 对局开始前确认，不使用战斗命令缓冲 |
| 返回、断线、终局 | 会话生命周期立即处理，清空待执行命令与表现队列 |
| 自动普攻、被动触发、兵线、死亡召唤 | 服务器自主规则，不因玩家操作缓冲再加0.5秒 |

目前没有第三类独立玩家战斗输入遗漏。未来增加定点技能、指定目标、手动控制/变形等，应扩展同一权威命令协议；投降走服务器会话裁决，匹配/准备走开局管理，不把所有界面按钮统一延迟。未增加玩家撤销已提交操作的功能，避免无意改变玩法。

## 实现要点

1. NetworkClock通过带会话/探测序号的独立通道采样RTT，以最近8次最低RTT估计服务器时钟；拒绝重复、未知与过期样本。服务器限制探测频率。时间估计不推进战斗。
2. NetworkCommandState保存公开命令ID、类型、阵营、卡牌/技能、位置、输入与执行Tick。服务器接受后立即通知两端；实际结果仍由服务器执行后发布。客户端只准备资源、显示本方等待状态，不提前生成实体、碰撞或伤害。
3. NetworkPlayback按服务器Tick应用快照及白名单战斗事件；同Tick先事件后快照，迟到追赶，终局立即应用最终状态并清空队列。可靠事件与可丢短音分通道；法术在途进度读取同一表现时钟。原有单位位置平滑保留。
4. 技能执行/取消都有带命令ID的完成通知；已接受请求取消不再通过提前拒绝回执清除按钮。重复完成幂等，不让旧命令清除同技能的新pending。客户端重复点击已pending出牌也被入口拒绝。
5. 更新快照之后到达的旧技能次数/CD通知不再覆盖新状态；快照先建立实体时，迟到可靠出生仍清除旧部署提示。技能存活但执行条件失效退款一次，死亡/终局关闭收据，沿用原政策。

## 实际渲染与故障验证

- [实际渲染三进程结果](../../../../ClashLegends-开发素材库/04-中间产物/构建与验证/buffer-network-render-final/result.json)通过。已目视检查双方视角、本方等待圆环和技能倒计时；例如[本方技能等待](../../../../ClashLegends-开发素材库/04-中间产物/构建与验证/buffer-network-render-final/client1-status-62.png)。普通模型、技能与终局继续由客户端表现。
- 最终集成检查双方都在目标Tick前收到双方出牌/技能排程、固定10Tick间隔、执行/取消结果、时钟同步及终局清场。
- impaired故障夹具：出牌/技能发送延后80ms、命令预告延后70ms、可靠战斗事件延后120ms、时钟响应延后40ms；普通快照丢弃1/3并交错20/120ms延后。最终双方公共/私有状态仍与服务器一致。
- 一次中间渲染运行因截图检查点增至5个、旧断言仍要求3个而失败；修正后重新运行并通过。最终全部结果来自修正后的代码。

## 遗留 / 未验证

- 500ms是权威命令缓冲，100ms是额外表现缓冲；后者增加视觉延迟，不改变服务器执行Tick。Tick量化、非对称网络、抖动、重传以及已有位置平滑意味着不能承诺点击后恰好500ms双方同时显示。超过命令窗口仍拒绝，客户端不自动重试；RTT/2不是非对称链路的精确单程测量。
- 客户端上报时间戳仍须服务器窗口约束，尚未做公网完整对抗性输入/限流与持续压测。公开预告在网络层包含对方已接受的操作，只在正常UI隐藏，不保证修改版客户端无法提前窥视。
- 未部署公网，未验证发行包跨机器连接，未实现匹配、账号、重连或多房间。大快照仍可能触发既有MTU警告，带宽/分片优化后续处理。
- 未新增声音资源；渲染运行保存录音且音频顺序自动检查通过，未把主观听感写成人工确认。
