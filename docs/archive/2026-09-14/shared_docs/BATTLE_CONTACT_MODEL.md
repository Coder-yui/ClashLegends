# 接触推行与局部避让

本轮依据用户提供的 Null's Royale APK 恢复普通移动接触的算法结构，替换完全非弹性追尾冲量。没有改卡牌的速度、半径、质量或其他平衡数据。它是适配 Clash Legends 的实现，不是完整皇室战争引擎或逐 Tick 等价复刻。

## 为什么快单位能推动慢单位

自主移动每 Tick 重新给出步幅。后排追上前排后产生接触，前排收到向前的位置修正，后排收到向后的修正。最终位移是自主位移加接触修正，所以前排能超过自身移速；推手离开后，下一个 Tick 就恢复自主速度，无需跨 Tick 保存动量。

旧实现使用质量加权的完全非弹性冲量，并将碰撞后的速度保存到下一 Tick，再追加另一套穿透修正。现已删除这条流程。

## 当前权威顺序

1. Unit 在固定 20Hz 下计算行为、目标与 `_move_intent`。
2. MovementSystem 按稳定 id 收集存活非建筑单位，用前方小范围查询决定局部偏转。同向行军不主动分离；遇到站定或对向友军时偏转方向，并重新归一化保持自主步幅。质量更大的已冲锋单位可跳过该移动邻居的避让。
3. 使用同一 Tick 的位置收集所有同空地层接触。单次贡献按 `对方质量 / 自身质量` 加权；每个单位将贡献求平均，再限制向量长度。不能按邻居数量无限累加。
4. 把接触修正与自主位移相加，统一交给现有桥岸、建筑和场地边界检测。主 Tick 不再追加第二轮碰撞修正，也不再在桥区把横向修正直接乘 0.15。
5. 接触不写回自主速度。站定单位的纯被动位移不触发自主移动的冲锋计时。项目原有 `charge_time` 语义仍然保留，没有换成原生 ChargeRange 数据。

`_resolve_unit_collisions()` 是领域测试使用的纯接触步，用于部署和变形几何验证；正常 `tick()` 已在移动中应用接触，不可重复调用它。

## 明确的适配边界

- 保留 Godot 浮点权威坐标；原生采用整数平方根、定点方向与向零截断，本实现不承诺逐位一致。
- 原生算法中的 1/300/150 等长度常量按 1000 原生坐标对应一个 40px 地图格换算；这是接触解算精度与步幅上限，不是导入卡牌数值。保持每 Tick 的含义，不能在更高频率上额外调用接触解算。
- 本项目先收集、后统一应用，以稳定 id 决定完全重叠的方向；原生对象 id 奇偶、执行顺序及全部邻域规则未作等价恢复。双方同 Tick 部署重叠时，以较新 id 作为落地者，保留项目已有的近塔挤位规则。
- 同层友军和敌军都参与实体接触，冻结/站定/部署单位可以被动挤开。原生特殊状态掩码、质量 `-1` 哨兵及绕过限幅的强制位移分支未一一映射；本项目仍使用现有 ControlState、部署和击退规则。
- 原生还有静态对象的转向分支与邻居转向借用。当前静态建筑通过现有路径与圆柱障碍约束；移动单位偏转取几何侧向和稳定 id，不借用另一单位本 Tick 已更新的转向值。
- A* 搜索核心已改为原生新版算法，见下节；圆形地形约束、桥角切线、目标落点修正与路径平滑尚未完成原生等价恢复。这些是暂存的适配层，不是必须保留的设计。已恢复的搜索数学不等于完整地形规则；不能把原生有限的“阻挡成本”直接替换为允许渡河。

## 半格 A* 核心

本机 M5 局部采样：128 单位索敌约 6.1ms，移动约 4.8ms，接触收集约 1.4ms。独立 120 次跨河寻路采样，旧内置 A* 中位数约 0.33ms、P95 0.53ms；新 GDScript 搜索中位数约 0.93ms、P95 2.46ms。因此搜索保真提升伴随 CPU 成本增加，不能声称性能没有回退；这些数字不代表整场 FPS 或手机性能。现有单位路线复用仍生效。
