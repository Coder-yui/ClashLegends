# Clash Legends 开发规划

> 类皇室战争玩法的个人学习项目，使用 LoL 角色题材，最终目标：与好友联网对战。
> 本文档是项目的总规划，里程碑更新时同步修改。

## 一、技术选型

| 项目 | 选型 | 理由 |
|---|---|---|
| 游戏引擎 | Godot 4.x 标准版 | 免费开源、轻量、GDScript 易学、2D 俯视视角足够 |
| 脚本语言 | GDScript | 与引擎深度集成，语法类似 Python |
| 代码编辑 | TRAE | AI 辅助开发 |
| 联网方案 | Godot Multiplayer API (ENet) | 一方做主机，好友直连，满足"只和好友对战"的需求 |
| 美术 | LoL 资产提取 + AI 生成（Seedream 插件）+ Krita 微调 | 个人项目，阶段 4 才接入 |
| 版本管理 | Git | 本地仓库即可 |

## 二、核心玩法定义（原型范围）

- 竖屏 720x1280 战场，上下两个半场，中间河道 + 两座桥；窗口下方另留 120px 手牌区
- 每方 3 座塔：2 座公主塔 + 1 座国王塔（国王塔被毁即输）
- 金币：上限 10，初始 5，每 2.8 秒回复 1 点
- 卡牌：消耗圣水部署单位，单位自动寻敌、移动、攻击
- 首批卡牌（占位数值，后续平衡）：
  - 盖伦 5 费（近战坦克）
  - 赵信 4 费（快速近战）
  - 艾希 3 费（远程射手）
  - 提莫 2 费（廉价远程）

### 阶段 1：核心原型（灰盒，无美术）
目标：验证核心循环成立。

- 全部用色块 + 圆形占位图
- 验收：能完整打完一局，有胜利和失败两种结局

### 阶段 3：联网对战（进行中）
- [x] 主菜单：单机 / 创建房间 / 加入房间（IP 输入）
- [x] ENet 连接（端口 39152），主机权威架构：战斗逻辑只在主机计算
- [x] 部署流程：客户端发 RPC 请求 → 主机校验区域/占位/费用 → 生成并广播
- [x] 20Hz 快照同步（单位位置/血量/冰冻、塔血量、双方金币、计时），客户端插值显示
- [x] 客户端相机翻转 180°（上方玩家视角），结算/冰冻特效同步
- [x] 核心机制第一轮校正：桥梁 A*、迎敌侧停位、视野仇恨/建筑拉扯、部署/首次攻击前摇、塔脱锁、集中式体积碰撞
- [x] 核心机制无界面回归检查（`tests/mechanics_check.gd`）及主机/客户端快照联调
- [x] 高阶机制第一轮：主机权威远程弹道、范围伤害、质量衰减击退、移动蓄力冲锋、破塔后的分路 pocket 部署区
- [x] 场地校正：18×32 格、40px/格、两格河道与三格桥、公主塔/国王塔镜像格位、格子化部署掩码
- [x] 拥挤移动校正：真实起点路径平滑、开阔地局部避让、桥区跟车队列、长时间河道越界检查
- [x] 静态碰撞校正：圆形塔、2x2 方形建筑、圆形单位连续碰撞、AI 统一部署校验、召唤物生成点合法化
- [x] 推进/锁敌校正：无仇恨单位遵循左右带权推进区并复用路径；攻击状态锁定目标至死亡或脱离射程
- [x] 移动观感校正：合法塔后出生不回退、普通攻击无击退、局部分离/预测避让、slop 穿透修正、转向平滑
- [x] 接触交互校正：桥角切线滑动、外角单位同侧绕塔、落地按体积/质量挤压及被挤出射程后重选目标
- [x] 参考项目地图校正：公主塔 y=6.5/25.5、三格桥、塔的视觉/部署/物理尺寸分离
- [x] 带权推进路线：移植 36x64 半格路线场，无仇恨路径复用，只在目标/障碍变化时重算
- [x] 逐卡视野与目标优先级：视野数据下放到 CardDB，普通单位在视野内统一选择最近的合法兵种/建筑
- [ ] 后续按新卡需要继续补齐：非追踪/穿透弹道、扇形伤害、死亡效果、眩晕/减速等独立状态
- [ ] 广域网联机：需路由器端口映射或内网穿透（Zerotier 等），局域网可直接玩

## 四、风险与原则

1. **先玩法后美术** —— 阶段 1-3 全部使用占位图，避免陷入美术泥潭
2. **战斗逻辑与表现分离** —— 阶段 1 起就保持逻辑纯数据化，为阶段 3 网络同步铺路
3. **每阶段可玩** —— 每个阶段结束都有一个能跑的版本
4. **个人学习项目** —— LoL 素材仅本地使用，不发布、不上架
