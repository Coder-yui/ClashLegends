# 移动、接触与寻路

当前实现参考原生算法结构，适配本项目地图与浮点坐标；不等于完整原版引擎或逐步完全一致的复刻。

## 快单位为什么能推慢单位

每个固定步先计算自主移动，再加接触造成的位置修正。后排追上前排时，前排向前、后排向后修正，因此前排可以暂时超过自身移速。推手离开后恢复自主速度，不保存跨步动量。

## 每步顺序

1. 单位计算行为、目标和移动意图。
2. 按稳定顺序查询邻居，处理局部转向；同向行军不主动分离，站定或对向邻居可触发避让。
3. 收集同一空地层的接触，按质量比计算贡献；每个单位求平均并限幅，不能随邻居数量无限累加。
4. 自主位移与接触修正一起经过桥岸、建筑和边界检查。
5. 接触不写回自主速度，被动推挤不计作自主冲锋移动。

普通击退也参与同层接触，并对本 Tick 相对运动做扫掠裁剪，防止高速穿体；地形沿途检查，撞停不侧滑，剩余行动锁继续。强制位移的条件穿障仅为[未实现设计](status/HARD_CONTROL.md#强制击退强制位移设计已确定尚未实现)。

正常移动已包含接触，不能再追加一轮碰撞修正。独立 `_resolve_unit_collisions()` 只用于领域测试中的纯接触步。

## 寻路与地图

搜索采用 20 单位半格、固定八邻接顺序、10/14 步进代价及原生堆同值处理。44 组原始搜索夹具验证逐格路线，见 `tests/fixtures/native_path_search.json`。

搜索能斜向展开不表示身体可以穿进建筑；实际移动仍检查圆柱身体和地图。桥上合法位置被斜向推挤时不能借河岸脱困容错进入河道。

## 已知边界

- 保留浮点坐标、稳定 ID 与先收集后应用的顺序，不承诺原生定点算法逐位一致。
- 特殊状态掩码、强制位移、邻居转向借用与动态拥堵规则尚未完整映射。
- 地形约束、桥角处理、目标修正和路径平滑仍有项目适配；原包地图掩码与本项目桥宽不同。
- 搜索路线吻合不证明完整对局轨迹相同，也不证明性能更快。历史采样曾显示搜索成本增加，完整对局仍需复测。

原二进制哈希、地址、夹具再生方法与当次性能/渲染证据见 [研究快照](archive/2026-09-14/shared_docs/BATTLE_CONTACT_MODEL.md)。当前验证覆盖推行、质量差、无残留动量、空地分层、密集限幅、过桥与塔前跟随；运行方式见 [测试手册](../tests/README.md)。

## 2026-09-19 局部接触解堵（收窄后的实现）

友军必须身体接触、位于前方，且不是同向行军，才请求局部侧转；不提前寻找攻击空位，不改目标或路径。同向推行、质量接触、控制与地形检查保留。大体型使用实际身体半径判定接触，避免已经相互推挤却未进入旧查询小圆。

敌军例外仅限双方都只攻击建筑、仍在相向自主行走且已经身体接触；共线时选择各自同一侧，解除互顶。盖伦遇到防守剑圣（行走或停步攻击）不新增主动侧转，仍走原接触推挤逻辑。条件按 gameplay 能力而非英雄名判定。

CR `0xf67360` 的移动邻居分支只在转向量为零时初始化 ±200；已非零时不会反复加满，静态邻居另有累积规则。本项目恢复这个初始化/衰减方式，撤销首轮修复的每步刷新；仍使用 200/256 混合与每 Tick 10/256 衰减。接触触发和建筑目标单位例外属于按用户要求收窄的项目适配，不声称已恢复原生筛选掩码。

协议版本和载荷以[网络契约](reference/NETWORK_PROTOCOL.md)为准。新增回归覆盖互顶、实际围攻，以及不提前避让、不绕防守者、不刷新转向等反向约束。详见[收窄交付记录](deliveries/2026-09-19_碰撞修复范围收窄.md)。
