# 音频接入流程

查看具体声音和试听，请从 [单位手册](units/README.md) 的音频页进入；全局声音归 [竞技场](units/audio/arena.md)。本页只说明通用接入过程。

## 先确认声音对应什么

按当前实际使用的动作列清单：出手、发射、真实命中、技能开始/持续/结束、出生与死亡。分别标为已接入、有意静音、缺素材或缺触发入口。

动画名、项目事件名与原始声音事件是三件事。不能仅凭文件名猜用途，也不能把原版所有技能声音都加进项目。未携带的技能不应发声；走路声明确不做。

## 接入步骤

1. **核对机制。**读取当前单位的玩法与动作，确认已有真实派发和消费入口；开发契约见 [事件参考](reference/AUDIO_EVENTS.md)。
2. **选择素材。**核对来源、皮肤、语言、事件与变体；外部源包只读提取，待开发队列按 [迁移规则](AGENT_WORKFLOW.md) 处理。
3. **加工与记录。**检查时长、采样率、声道、静音、截断和爆音。不要逐文件强行归一化而破坏原有层次。来源及处理写入素材清单。
4. **配置。**在该卡音频域登记声音池、音量、事件和必要阵营覆盖；随机变体不能冒充不同条件。
5. **验证。**先试听素材，再在实战中检查真实时机、并发、中断和清理。更新单位音频页的中文说明与缺项。

没有声音可暂时留空并说明原因，不能用假静音文件或不相关技能充数。需要解析源包时另读 [来源与转换参考](reference/AUDIO_SOURCE_PIPELINE.md)。

## 关键边界

- 远程命中声在真实碰撞结算成功时播放，不在发射时提前播放。空挥、免疫与取消不伪造命中。
- 弹体保存出手时的来源、形态和阵营；来源死亡或变形不改变在途弹体的声音归属。
- 持续音要明确持有者及停止条件。单位、区域、弹体与系统建筑分别管理，不能一律跟随施法者死亡停止。
- 0 dB 表示不额外增益，不代表响度相同。声音不会随普攻速率全局变调。
- 不通过改变攻速、伤害或施法时间来配合声音；只调整音频素材或表现排程。

## 工具与重导入

工具集中在 `tools/audio/`。通用导入必须明确卡牌范围，并先预览：

```sh
python3 tools/audio/import_card_audio.py --source /absolute/path/to/prepared_library --cards <card_id> --dry-run
```

移除 `--dry-run` 才写入选定内容；可用 `--plan` 指定审核后的计划。特殊导入器常有本机路径与当次加工假设，重导前核对当前定义及 manifest，不能批量覆盖后续调校。

## 验收

运行 [核心回归与审计](../tests/README.md)，检查资源、分段映射、去重和生命周期。实战还需听双方、不同距离、并发单位、命中/未命中、控制恢复和死亡清场；改变网络事件时检查主客双方。

素材播放成功只证明文件可用；事件日志只证明触发；最终听感仍需实际试听。来源与详细验收留在素材记录或归档，单位音频页保留易读的当前说明。
