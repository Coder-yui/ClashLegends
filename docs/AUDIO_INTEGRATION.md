# 音频接入流程

查看具体声音和试听，请从 [单位手册](units/README.md) 的音频页进入；全局声音归 [竞技场](units/audio/arena.md)。本页只说明通用接入过程。

候选音频先存项目根目录素材库 `02-候选讨论/`，制作与裁剪在 `03-制作中/`，试样和录音放 `04-中间产物/`。复用 `tools/dev.py audio` 按目录或清单试听；确认接入后才移动最终音频到 `assets/audio/` 并登记事件。

## 先确认声音对应什么

按当前实际使用的动作列清单：出手、发射、真实命中、技能开始/持续/结束、出生与死亡。分别标为已接入、有意静音、缺素材或缺触发入口。

动画名、项目事件名与原始声音事件是三件事。不能仅凭文件名猜用途，也不能把原版所有技能声音都加进项目。未携带的技能不应发声；走路声明确不做。

## 接入步骤

1. **核对机制。**读取当前单位的玩法与动作，确认已有真实派发和消费入口；开发契约见 [事件参考](reference/AUDIO_EVENTS.md)。
2. **选择素材。**核对来源、皮肤、语言、事件与变体；外部源包只读提取，待开发队列按 [迁移规则](AGENT_WORKFLOW.md) 处理。
3. **加工与记录。**事件生成必须显式使用 wwiser `-gv=0dB`，拒绝 auto/非零工具主增益；导入重新解码，不能复用旧预览缓存。检查时长、采样率、声道、静音、截断和爆音。不要逐文件强行归一化而破坏原有层次。来源及处理写入素材清单。
4. **配置。**在该卡音频域登记声音池、音量、事件和必要阵营覆盖；随机变体不能冒充不同条件。
5. **验证。**先试听素材，再在实战中检查真实时机、并发、中断和清理。更新单位音频页的中文说明与缺项。

没有声音可暂时留空并说明原因，不能用假静音文件或不相关技能充数。需要解析源包时另读 [来源与转换参考](reference/AUDIO_SOURCE_PIPELINE.md)。

## 关键边界

- 远程命中声在真实碰撞结算成功时播放，不在发射时提前播放。空挥、免疫与取消不伪造命中。
- 弹体保存出手时的来源、形态和阵营；来源死亡或变形不改变在途弹体的声音归属。
- 持续音要明确持有者及停止条件。单位、区域、弹体与系统建筑分别管理，不能一律跟随施法者死亡停止。
- 0 dB 表示不额外增益，不代表响度相同。声音不会随普攻速率全局变调。
- 不通过改变攻速、伤害或施法时间来配合声音；只调整音频素材或表现排程。

## 工具与重导入

工具集中在 `tools/audio/`。通用导入必须明确卡牌范围，并先预览：

```sh
python3 tools/audio/import_card_audio.py --source /absolute/path/to/prepared_library --cards <card_id> --dry-run
```

移除 `--dry-run` 才写入选定内容；可用 `--plan` 指定审核后的计划。特殊导入器常有本机路径与当次加工假设，重导前核对当前定义及 manifest，不能批量覆盖后续调校。

当前 LoL 正式音频采用原版事件增益基准，后期固定增益为 0 dB；游戏内事件的播放补偿为 0 dB。部署池中混用的客户端选人/禁用语音通过 `audio.events["deploy:voice"].clip_volume_db` 按资源路径单独补偿，未列出的成员保持事件原增益；该字段仅支持部署语音，保留等概率且不连续重复的选择规则。冰冻来自独立的皇室战争素材，保留原资源，单独以 -12 dB 固定播放增益匹配控制类法术响度；这不是自动增益或文件归一化。必要裁剪、变速、淡入淡出与空间衰减仍保留；逐文件来源、参数和哈希见 `assets/audio/original_gain_manifest.json`。原版 OGG 解码超量程的两条语音保留原始封装，不进行自动衰减或有损重编码。

## 验收

运行 [核心回归与审计](../tests/README.md)，检查资源、分段映射、去重和生命周期。实战还需听双方、不同距离、并发单位、命中/未命中、控制恢复和死亡清场；改变网络事件时检查主客双方。

素材播放成功只证明文件可用；事件日志只证明触发；最终听感仍需实际试听。来源与详细验收留在素材记录或归档，单位音频页保留易读的当前说明。

## 并发预算与诊断

短音上限 24，其中 4 个位保留给技能、死亡和 Voice 事件。优先级依次为普通出手/飞行、命中/强化、技能语义事件、死亡/语音；满池先替换较低优先级、同级较早开始的声音，低优先级不能打断高优先级。播报独占 1 个全局播放器，不参与短音竞争。

单位持续声上限 24，技能/Buff/复生优先于持续攻击，待机最低。独立区域、在途发射声和系统建筑各有独立上限 24；区域/弹体满池替换最早实例，系统建筑超过上限拒绝新实例。建筑出生与待机同时启动时最多保留一条自然结束的出生尾音。计数只衡量当前逻辑占用，排队释放的节点可能短暂存在到帧末。

`GameAudioManager.budget_snapshot()` 返回各类当前占用、上限、峰值、成功开始数、预算丢弃数和预算打断数；正常结束、死亡清理不计入预算打断。`begin_battle()` 重置本局计数，`end_battle()` 保留诊断并清空占用。未配置/不可用事件不算预算丢弃。

单次、持续、在途命中/发射、区域与卡牌事件统一先选择形态再应用阵营覆盖；区域和卡牌 RPC 携带来源阵营。覆盖 `events` 时按当前浅合并契约替换整个事件表，不能假设自动逐事件继承。听感仍需结合实际对局试听判断，预算断言不能替代混音验收。

水晶终局序列通过 GameAudioManager.finish_match_audio 管理本局独占爆炸实例，可靠终态应用后按最终塔血量补足触发并去重。end_battle 默认清理全部声音；终局内部显式保留该次爆炸，红蓝方均按爆炸实际播放位置在 5.0 秒启动胜负播报。播报 finished 后用 1 秒淡出本局剩余播放器，并发出 terminal_audio_finished；仅防御塔判胜时立即播报并执行同样淡出。begin_battle、菜单退出及场景释放使旧代次回调失效。battle_audio_stopped 只检查常规战斗层，水晶尾音由独立序列验证；正常主动停止不等于自然完成。

开局加载阶段按双方卡组递归准备全部音频池，包含形态、召唤物、世界建筑及比赛播报；只建立资源，不播放音轨、不发出音频事件。运转循环提前准备对应循环资源，避免首次播放创建音轨。

## 通用混音动态处理

`default_bus_layout.tres` 统一控制叠加电平，不按卡牌、目标数或事件名降音量：

| 总线 | 处理 | 参数 |
| --- | --- | --- |
| Combat | 压缩器 | 阈值 -18 dB，比例 2:1，启动 2 ms，释放 160 ms，补偿 0 dB |
| Voice | 独立压缩器 | 阈值 -16 dB，比例 2:1，启动 3 ms，释放 180 ms，补偿 0 dB |
| Master | 硬限幅 | 上限 -1 dB，释放 100 ms，预增益 0 dB |

Combat 经 SFX 汇入 Master；Voice 直接汇入 Master，不受 Combat 压缩器控制。所有经过这些总线的现有/新增音效，包括持续声和不同卡牌混播，都自动接受处理。原素材、卡牌单音效和客户端部署语音固定补偿保留；阈值以下不主动增益。较响的单个音效也可能触发压缩，按实际电平判断而非声源数量。总限幅可能在极端混音时同时影响语音和战斗层，属于最终输出保护。

之前 100 ms 内按数量计算的出生、凝滞、死亡与攻击并发衰减已撤回，避免与总线重复处理。原有声部数量和优先级预算继续负责资源占用。验证需包括低电平单声源、同类叠加、不同类型混播及过载尖峰；阈值/启动/释放须结合录音检查，不能仅靠单音效响度判断。
