# 动画与动作时序

本页解释共用行为；具体单位的片段与观看说明见 [单位手册](units/README.md)，开发字段见 [动画配置参考](reference/ANIMATION_CONFIGURATION.md)。

## 动作如何选择

基础状态是部署、待机和移动，上面可覆盖攻击、技能、变形和死亡动作。

优先级：**死亡 → 部署 → 变形 → 技能 → 普攻 → 待机/移动**。高优先级动作结束后，按最新战斗状态接回攻击、移动或待机。

战斗逻辑提供动作和时间进度；动画只负责表现，不能通过“播放完成”触发伤害、位移、索敌或复活。

## 施法与控制

| 情况 | 行为 |
| --- | --- |
| 默认站定施法 | 锁定移动、普攻和朝向 |
| 明确允许移动的技能 | 依配置保留移动权限；全身技能动作仍须锁普攻 |
| 冰冻 | 保持命中时姿态，取消依附施法的未释放后段与完成奖励 |
| 眩晕 | 已开始普通技能的动作、声音及合法后段继续；其他动作按当前权限显示眩晕 |
| 冰冻与眩晕重叠 | 冰冻也会暂停眩晕表现 |
| 攻速变化 | 同步调整普攻当前阶段和播放速度，不从头重播 |
| 死亡 | 接管表现并解除控制覆盖；未发生的技能效果取消 |

施法总时长和效果执行延迟都从施法开始计时，命令缓冲另算。效果执行可能是直接伤害，也可能只是发射弹体或生成区域；目标是否受伤由对应命中判定决定。已经生成的独立区域和弹体按各自生命周期处理，不能随施法者死亡一概取消。

## 连续动作

有专门收势或转跑素材时先使用它；没有时用姿态混合过渡。进入跑步只选一条过渡路线，不把专用转跑和通用入跑连续叠放。

多段攻击、剪切与变形可按原片区间组合；素材裁剪只改变表现。新攻击即使与上次片段同名，也必须从本次正确进度开始，不能停在上次末帧。

第一次接敌正常开始前摇，不预先装满一个攻击间隔。取消尚未出手的前摇不产生冷却；已出手后的再次接敌仍受真实剩余冷却约束。

## 联机与实例隔离

客户端按主机动作序号和进度播放，重复快照不重播，晚到则定位到当前阶段。动画资源按实例隔离，避免一个单位修改循环方式影响其他单位。

头顶锚点应稳定；没有专用锚点时，只在接入或换模型时计算回退位置，不能逐帧追随武器或披风最高点。死亡后续模型只负责表现，不延长存活。

修改后检查连续攻击、取消/恢复、控制叠加、死亡与双方联网进度。测试入口见 [测试手册](../tests/README.md)。

## 共同术语与时间单位

| 名称 | 含义 |
| --- | --- |
| 命令接受 / CommandAccepted | 请求通过资格检查并入队；不表示已施法或命中 |
| 施法开始 / CastStart | 锁定本次技能资源和朝向，扣次数并启动冷却 |
| 效果执行 / EffectExecution | `impact_delay` 或多段配置指定的规则节点；可以是直接结算、加状态、创建区域或发射弹体 |
| 发射 / Release | 真实弹体或区域产生；纯表现飞行另由表现配置控制 |
| 碰撞命中 / CollisionImpact | 弹体与目标实际相交后执行命中、伤害或状态；不等于配置中的 `impact_delay` |
| 收招 / Recovery | 出手或效果之后恢复行为的阶段；动画不能自行解除规则锁 |
| 金币 | 界面用词；旧代码类型 `ElixirManager` 和 `elixir` 字段仍表示同一资源 |
| 卡牌开发工作台 | 预览与场景实验入口；旧 `art_dev` 字段是内部实现名，不代表正式对局规则 |
| 主动技能 | 用户称呼；`active_skill` 表示技能定义/流程，`ability_id` 标识本场已注册的技能资格实例 |

配置秒数、固定模拟 Tick 和渲染帧分别记录。20Hz 每 Tick 为 0.05 秒；从 Tick 边界开始的正延迟通常在 `ceil(秒数 / 0.05)` 个后续 Tick 到期，排程浮点容差为 0.001 秒。0 秒效果在 CastStart 直接执行；0.16 秒在第 4 Tick、0.72 秒在第 15 Tick 执行。控制取消与独立结果归属见[动作合同](status/ACTIONS.md)，不采用解控后统一续播。

本 Tick 新接受执行的技能不提前消耗其效果延迟。效果队列先推进，之后处理新命令；弹体在 Tick 后部推进，所以刚发射的弹体可在同 Tick 命中近目标。模型和声音按这些权威节点表现，不使用渲染帧号作规则计时。稳定卡牌 id、RPC 字段、资源路径及源音频事件名不随中文术语统一而重命名。
