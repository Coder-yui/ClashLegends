## 当前设计接入要求

规则正文分别由[硬控](HARD_CONTROL.md)、[动作](ACTIONS.md)、[特殊状态](SPECIAL_STATES.md)、[增益](BUFFS.md)和[表现](PRESENTATION.md)维护，此处只列接入检查点。

| 领域 | 实施要求 |
| --- | --- |
| 攻击打断 | 取消旧前后摇/间隔，按近战命中或远程创建弹体维护段号；不要重置整个循环 |
| 控制响应 | 分开眩晕与冰冻；普通技能/转换/部署对五类控制继续，对冰冻/凝滞立即冻结并按各自规则结束 |
| 嘲讽 | schema/validator 禁止空中单位/形态提供能力；运行时检查来源，到期清除强制目标并重新普通选敌，不保留强制追击路径 |
| 凝滞 | 保留碰撞且不可推动，进入不额外整理位置；下牌冲突只调整新单位到最近合法落点，结束恢复现有接触分离。拒绝选取/伤害/新 Buff，已有 Buff 抑制且照计时 |
| Buff 生命周期 | 抑制、恢复、自然到期与重新施加分开；不因解除凝滞重发加血、周期收益或获得音 |
| 纳尔 | 命中计数与攻击段分开；只在冰冻/凝滞时记录一次待变形，两者都解除即可触发，其他控制仍有效 |
| 音频所有者 | 分开动作、命中、弹体、Buff、区域；取消动作不误停独立声音，也能停止已播放的挥舞声 |
| 联网 | 同步足够的当前权限、动作身份及抑制表现，重复/晚到消息不能恢复已取消动作 |

当前尚需具体化的内容：位移技能截停后的各段归属、入场首批召唤归属、跨模型冻结姿势衔接；相关卡牌接入前须有明确规则和验证。仍标注“暂定”的数值、隐身等专题按其所属页继续评审。

动作接入还须覆盖：完整攻击周期与同目标嘲讽、技能动作与位移保护分离、转向权限、解控后的强制形态变化优先级。生命周期维护独立于可取消的战斗完成奖励；控制新增/刷新/抑制恢复事件分开。凝滞拒绝重复施加，退出不重施旧控制；净化复用恢复流程。特效与声音按所有者取消，避免冻结或清理整个单位的全部表现。对应规则见动作、特殊状态、共通规则与表现合同。

## 实施职责与顺序

以下为建议职责，不要求机械地按每一行新建一个文件。已有职责合适的文件应直接扩展。

| 所有者/入口 | 建议职责 | 从现有实现迁移什么 |
|---|---|---|
| `StatusState`（新） | 效果实例、刷新/移除、周期调度元数据、聚合结果 | ControlState 计时、Unit 的公共主动增益字段与致盲状态 |
| 交互规则入口（新或放入既有战斗服务） | 敌我目标、命中、加状态、治疗、护盾的准入 | 分散的 hidden/shroud/immune/hp 判断 |
| `AttackTimeline`（保留） | 普攻阶段、节奏、攻速重标定、动作 ID 关联 | 不让状态执行器直接改三套攻击计时器 |
| 施法时间线（可从 Main 排程中抽出） | CastStarted、分段释放、取消、结束与收据关联 | 避免 Main 和 Unit 各持有互不一致的“正在施法”真相 |
| 位移状态（从 Unit 集中） | 离散轨迹、接管/替换、外力贡献 | `_knockback_timer/velocity` 和后续推拉/吸引 |
| `MovementSystem`（保留） | 实际位移、地形、分离、空地碰撞层 | 不让状态直接写世界坐标绕过碰撞 |
| `ShieldState`（保留） | 盾层、衰减、抵伤、到期原因 | 不重复创建另一套盾时钟 |
| `CombatResolver`（扩展） | 阶段内请求、伤害/效果回执、存活收益、确定性提交 | 纯控制不能依赖扣血成功；治疗不能提前读取未结算的 HP 差 |
| `CommandSchedule / CommandPayment`（保留） | 请求资格与费用生命周期 | 打断不能重复退费或重复消费 |
| `UnitPresentationState`（扩展） | 向本地/联网表现发布同一只读视图 | 扩展现有 frozen/stunned/动作序号，而非各表现自行推断 |
| `UnitModel3D / GameAudioManager`（扩展） | 状态/动作实例对应的表现与清理 | 从“全局暂停旧动作”改成按生命周期取消/继续 |

旧接口如 `freeze()`、`stun()`、`apply_slow()`、`apply_knockback()` 可在迁移期保留成薄适配器，但只向新的唯一所有者提交请求，不能同时写旧计时器与新实例。

新增内容继续放卡牌 gameplay/visual/audio 对应域；逻辑字段与素材字段分开。新字段必须有读取方、范围/类型校验、目标能力检查与测试。未实现的效果类别应在载入时明确拒绝，而不是让 Agent 配出一张“只有配置、没有机制”的卡。

先为现有行为建立特征测试；再统一准入和状态所有者；然后按明确采用的规则迁移动作、计时、网络与表现；最后按出卡需要增加原语。每批单独验收，不长期并存两套生产玩法。对照用例见[验收清单](VALIDATION.md)。

## 网络与性能

权威实例只在主机推进；客户端不得根据渲染时间自行判定解除眩晕、毒伤、护盾到期或重新取得攻击资格。客户端可以插值/估计剩余时间用于显示，但玩法结果以主机状态为准。

扩展快照应传递必要的权限、表现家族、动作身份/代次、阶段进度、可见性相关视图和盾量等，而不是复制所有执行器内部字典。短暂动作取消、状态开始/结束使用现有事件通道可靠去重，快照再作状态收敛。事件过时或所属动作已取消时，不补播过期技能。

实施前读取实际协议与载荷定义；新规则/载荷同步提高协议版本、更新双方读写与内容校验，不声称旧客户端可无修改兼容。当前核对版本见本页首表。

隐身不仅是表现问题。面向敌方发送的数据应按可感知范围裁剪隐藏实体的非必要精确信息；尤其不能在隐藏模型后仍通过选择列表和调试式状态广播直接透露位置。若阶段性仍采用完整状态同步，必须明确记录这只是本地视觉隐藏、并不具备对恶意客户端的信息隔离能力。

性能实施原则：按来源/目标维护紧凑实例；同一区域续期同一实例而非每 Tick 分配新对象；权限/数值只在增删、强度改变、抑制改变时标脏重算；复用现有目标查询和移动几何；不让所有状态各自扫描全体单位。死亡、形态切换、清场和模型池回收及时释放引用。

验收记录状态实例峰值、每 Tick 推进耗时分布、区域目标数、网络快照字节数、音轨数与表现丢弃数。不能仅凭代码看起来更抽象就宣称性能提高；战斗过程流畅性仍优先于减少开局预加载。

## 特效挂载与控制时钟现状

`BattleEffects2D._draw_frontal_skill_effect` 对非固定范围特效读取来源模型显示位置，符合随身技能范围跟随位移的规则；`ProjectileSystem.launch_skill_fan` 保存创建位置/方向，后续独立推进；`UnitModel3D` 将 ActiveBuffVisual3D 挂为子节点并独立 advance，符合随身 Buff 挂载。

`ActiveSkillEffectSystem.tick_visuals` 按动作身份清理依附施法的范围：眩晕继续，冰冻取消。固定独立区域和星辰按自身时间推进；`apply_frontal` 仍按每次结算的位置查询目标。凝滞未实现，不能宣称已验证。实际画面与声音的验收状态见交付记录。
