# 共通规则：实例、权限、叠加与时钟

> **当前设计，尚未实施。**本文规定目标行为；当前代码支持情况见[实现现状与接入](IMPLEMENTATION.md)。

[返回总览](README.md)

主机/单机固定 20Hz 权威模拟，客户端仅请求操作并消费快照/表现事件；动画、特效、音频不驱动战斗。普通单位继续使用 CardDB + 通用 Unit；经 BattleContext 获取服务。卡牌动作走 `play_card()`，生成走 `_spawn_unit()`，法术走 `_cast_spell()`；共享定义只读，运行实例独立持有状态。

## 基本模型

### 状态不是动作，动作不是表现

一个单位可以同时“中毒、加速、被禁锢、带盾、正在普攻”。这不应该变成五个互斥状态。

| 维度 | 所回答的问题 | 典型内容 |
|---|---|---|
| 生命周期 | 这个实体现在是否存在、能否参与战斗？ | 部署中、存活、已判死、死亡表现、替身/复生 |
| 效果实例 | 身上正在携带什么规则？ | 眩晕、减速、护盾关联、毒、隐身、增益 |
| 动作时间线 | 单位正在做哪一段行为？ | 普攻等待、前摇、出手、后摇、持续喷吐；技能前摇、持续段、收招 |
| 权限与交互 | 现在能行动吗？某个来源能否选中、命中、治疗它？ | 能否走路/普攻/施法，敌我交互、可见性 |
| 运动执行 | 最终位置由什么贡献决定？ | 自主移动、冲刺、受控位移、吸引、碰撞修正 |
| 表现 | 玩家应该看到、听到什么？ | 基础动作、控制姿态、材质、音轨、图标 |

“硬控/软控/增益/减益”用于描述和检索，**实际限制必须由权限和效果类别决定**，不能写成“只要硬控就禁止所有行为”。禁锢就是反例。

### 建议提供的权限视图

行动侧至少区分：`can_move_voluntarily`、`can_start_basic_attack`、`can_continue_basic_attack`、`can_start_skill`、`can_continue_skill`、`can_turn_voluntarily`、`can_receive_external_motion`。

交互侧使用带上下文的查询，而不是一个全局布尔值：

```text
can_acquire_target(source, target, targeting_kind)
can_deliver_hit(source_context, target, delivery_kind)
can_apply_status(effect_context, target)
can_receive_heal(heal_context, target)
can_receive_shield(shield_context, target)
is_visible_to(target, observing_team)
```

上下文包含来源阵营、来源身份、目标种类、作用方式、是否已附着、是否属于控制、空间限制等。同一个目标对敌军和友军可以有不同结果。

禁用权限按所有有效来源合并。已开始的保护动作通过动作实例的继续执行许可单独判定，不把单位的全局攻击/技能权限设回允许；保护范围见[动作合同](ACTIONS.md)。解除禁锢时，不能直接写 `can_move = true`，因为单位可能仍被眩晕、施法移动锁或先锋恢复锁限制。

### 控制、增益、伤害统一接入，但不强求一个类拥有一切

推荐统一的是施加入口、身份、生命周期事件和准入规则，而不是把所有数据塞进 `StatusState`：普攻时间线仍归 `AttackTimeline`；护盾层仍归 `ShieldState`；施法实例归施法时间线；轨迹归运动执行器。各自只有一个权威所有者。

例如，施加护盾经统一交互检查后，交给 `ShieldState` 创建层；状态图标可以引用这层的句柄，**不能再另建一个不同步的“护盾剩余秒数”**。

### 原语与组合的边界

本方案不新增魅惑、恐惧、击飞、缚地、昏睡、石化、压制等独立控制类型。后续需要相似表现时，先判断能否用现有原语表达，不因动画或技能命名不同就复制执行逻辑。

“击退 + 眩晕 + 伤害”由三个具有同一来源上下文的子效果组成，各自按规则准入：目标仅免疫位移时，可以原地受到眩晕和伤害；目标控制免疫时，可以只受到伤害；目标凝滞时三者都被拒绝。组合不自动意味着三个子效果必须全部成功，也不意味着一个子效果失败就撤回其余已成立结果。需要全有或全无的特殊技能必须另行明确事务规则。

这种组合可以表现为“被吓退”，但它机械上仍是既定轨迹加不可行动，不自动获得“持续自行逃离施法者”的目标决策能力；卡牌说明应描述真实效果。

## 效果实例与叠加

### 定义与实例

效果定义只读；实例保存运行数据。建议最小数据如下，属于拟议契约，不是现有字段：

| 字段 | 用途 |
|---|---|
| `definition_id / instance_id` | 区分规则定义与本次施加 |
| `source_entity_id / source_generation / source_team` | 来源、归属与死亡后的归因；不用对象地址作权威排序身份 |
| `target_entity_id / target_generation` | 防止旧回调影响复用 ID 的新实体 |
| `start_tick / end_tick` | 效果窗口；无期限必须显式声明 |
| `family / tags / polarity` | 机械类别、控制标签、增益或减益属性 |
| `stack_key / stack_policy` | 同一来源刷新、独立实例、替换、次数叠加等 |
| `potency / charges / periodic_state` | 数值强度、次数、周期进度与小数余量 |
| `owner_lifetime` | 独立到期、依赖区域、依赖施法、依赖来源存活 |
| `suppressed` / 抑制原因 | 区分实例仍存续和效果是否贡献；凝滞期间 Buff 计时但不生效 |
| `presentation_profile` | 材质、动作、声音等表现选择；冰冻/眩晕的不同打断规则由各自权威类型定义，不由此字段决定 |

不要为每个效果创建 Node、Timer 或每帧协程。优先使用轻量运行对象/类型化容器，由固定模拟统一推进。

### 施加流程

施加请求先校验数值、实体代次、阵营/目标类型和作用范围，再检查凝滞、交互保护、免疫及效果自身要求。被拒绝的效果不得取消旧动作、覆盖旧位移、扣致盲次数或播放“控制成功”声音。

嘲讽另检查来源当前为地面单位；空中单位/形态不得提供该能力。凝滞分别拒绝目标选取、新效果和伤害；不能用关闭碰撞代替门禁。

凝滞期间拒绝新增状态，包含再次施加凝滞，不能用同源刷新绕过准入。通过准入后才创建/刷新实例、重新计算权限、执行必要的动作中断，并发布一次状态事件。重复刷新只更新真实改变的字段，不应每 Tick 重播眩晕起手或音效。

移除原因必须区分：自然到期、消耗完毕、被替换、净化、来源/区域消失、死亡、清场。只有明确声明的回调能在相应原因下执行。例如恢复护盾不能把“被打破”当作“自然到期”。

### 控制事件与被动触发

成功新施加、已有实例刷新、效果抑制/恢复、实际动作打断是不同事件。默认受控触发被动只响应成功新施加，不因同一实例刷新、从抑制中恢复或快照重放反复触发；动作被打断的被动只响应真实取消一次。被拒绝请求不产生成功事件。

普通硬控不默认关闭所有被动。反伤、受击触发等不依赖自主行动的效果仍按自身触发条件执行；依赖新攻击、施法或周期行动的产出须检查相应权限。凝滞中已有 Buff 的数值、触发和光环贡献按凝滞规则抑制，不能通过“被动”名义绕过。

### 推荐叠加规则

| 类别 | 推荐规则 |
|---|---|
| 冰冻/眩晕、禁锢、沉默 | 各实例独立到期；只要有有效实例就保持对应限制。持续时间不直接相加。 |
| 同一家族控制重新命中 | 同一来源同一效果默认刷新至 `max(旧结束时刻, 当前时刻 + 新时长)`；新的独立来源独立保存。 |
| 冰冻 + 眩晕 | 不同控制类型，独立到期并合并权限。冰冻额外冻结模型并取消技能后段，不能因已有眩晕跳过；对同一已取消动作不重复取消。 |
| 减速/减攻速 | 各实例独立计时，只取当前有效实例中最强的一项。 |
| 加速/加攻速/同类增伤 | 各实例独立计时，同一数值组取当前最强的一项。 |
| 致盲次数 | 剩余整数次数取最大、不相加；正式出手消费，龙王普攻不受影响且不消费，详见[减益与软控制](DEBUFFS.md)。 |
| 嘲讽 | 不同来源的新有效嘲讽替换旧嘲讽；旧嘲讽不排队复活。同一来源刷新时不重复打断。 |
| 击退/强制位移 | 有效的新位移替换当前轨迹；不是距离相加，也不是速度矢量相加。 |
| 持续吸引 | 多个有效区域的力矢量合成，并设总速度/加速度上限；不是轨迹替换。 |
| 护盾 | 保留独立盾层、独立时长和衰减。 |
| 流血/中毒、持续治疗 | 默认同一效果同一来源刷新、不叠强度；不同来源分别结算。需要层数机制时必须显式声明。 |
| 隐身 | 任意有效隐身实例维持对应隐藏权限；触发破隐时移除本次事件应打破的全部隐身实例，避免另一层马上让单位继续隐身。 |

**变化示例：**先有 0.5 秒、移速乘 0.3 的减速，再有 4 秒、移速乘 0.8 的减速。建议前 0.5 秒取 0.3，之后只取 0.8；不能把 0.3 延长到 4 秒。增益同理：2 秒攻速加成不能被另外 8 秒的移速加成延长。

同一来源重施不同强度时，新包整体替换旧包的强度与结束时刻（当前 Tick + 新时长）；同强度刷新才保留较晚结束时刻。不要再次分别拼接“历史最强强度”和“历史最长时间”。确需保留两次不同强度的尾段，就使用独立实例策略。

## 时钟与结算

### 时钟原则

状态时长、增益时长、技能冷却、护盾到期/衰减、部署时间、转换窗口、自然寿命以权威模拟时间推进，不由当前动作是否能执行决定。未取消普攻的有效间隔正常计时；普攻被硬控实际打断时，其旧间隔作废，解控即可重新前摇，见[动作合同](ACTIONS.md)。**受控不是暂停游戏时间。**

普通前摇/持续动作遭遇中断后，旧实例已结束，不再存在“暂停的旧前摇”。未被中断的权限锁或强制恢复窗口继续计时。

新增定时状态使用整数 Tick 的结束时刻：20Hz 下每 Tick 为 0.05 秒，正时长向上取整到可表达的 Tick；0 或负时长不形成控制，不触发打断。不能对刚施加的效果再立即扣掉一个 Tick。现有普攻节奏中的小数时间/余量可继续由时间线持有，不要未经评估把所有卡牌节奏粗暴改成 0.1 秒档位。

工作台/整场暂停才停止整场模拟时间；凝滞与眩晕都不是整场暂停。实例存续不等于生效：凝滞期间已有 Buff 计时但贡献被抑制，解除后只恢复仍有效的实例；不重播获得事件，不重新计算完整时长。

### 周期效果边界

默认首次周期结算发生在施加后的一个周期，而非立即额外结算。`duration=3s, period=1s` 默认在第 1、2、3 秒各结算一次；固定每跳伤害默认不补非整周期尾跳；按 DPS/HPS 预算的效果可结算剩余有效时间份额，必须明确模式，不允许凭渲染帧数多打一跳。

在某 Tick 开始时，先整理状态到期与当前交互权限，再处理该边界到期的周期结算记录；允许处理恰好落在效果结束时刻的最后一次记录，但实例不再影响之后的行动。凝滞恰好在该边界结束时，边界上的新一次毒伤可以命中；凝滞期间错过的旧跳数不补发。

### 保留阶段内同时结算

保留现有各战斗阶段的相对顺序，而不是把整个 Tick 混成一批。新增周期状态阶段可放在现有战斗阶段之前；这一新增先后关系属于规则变更，必须有协议版本和边界测试。

每个阶段先固定合法参与者、目标、到期命中与效果请求，再批量提交伤害、附带状态、存活收益与死亡。**同一批次已经提交的合法攻击，不因该批新到达的眩晕或死亡被追溯撤销。**较早阶段已生效的控制则能阻止后续阶段尚未提交的行为。这保留近战双方同刻致死的对称性。

同批次新施加的护盾、凝滞或免疫，不追溯保护本批已锁定的伤害；同批效果准入使用该批捕获的交互视图。需要“先保护、后承受另一击”的机制，应安排在更早的正式阶段，不能依赖遍历单位的先后顺序。

### 回执与伤害分离

建议效果/命中结算返回明确回执：

```text
request_accepted        请求形式与目标准入通过，不等于已经命中
hit_delivered           本次命中实际成立
hp_lost / shield_lost   真实扣血与耗盾
status_applied[]        实际附加了哪些状态
rejected_reason        凝滞、免疫、目标类型不符、目标失效等
```

护盾吸收了全部伤害，仍可算命中并附加眩晕；伤害为零的纯控制，也能独立施加。反之，不能因为伤害请求被排入队列，就提前播放命中音、回血、加层或附带控制。

所有治疗收益以结算回执计算。凝滞拒绝治疗不属于“治疗溢出”，不能把被拒绝的治疗量转成护盾。
