# 协作任务导航

先检查 `git status --short --branch`，保留已有修改；共同边界见 [AGENTS](../AGENTS.md)。本页负责选择阅读路径，完整制作步骤只在 [新卡清单](NEW_CARD_CHECKLIST.md) 维护。

## 按任务选读

一个对话通常对应一个任务。完整新卡的机制、模型动画、卡面图标、声音、特效、联调及反复调整属于同一周期；已有内容的一项小改动无需重走新卡全流程。大任务可由需求文档说明，小任务直接按对话执行，不要求填写模板。

| 任务类别 | 最少阅读与修改入口 | 验证范围 |
| --- | --- | --- |
| 新卡开发 | [新卡清单](NEW_CARD_CHECKLIST.md)、[卡牌机制](CARD_DESIGN.md)；逐卡定义及注册，再按下面素材专题选读 | 机制、模型动画、卡面图标、声音、特效与联合验收，反馈继续本周期 |
| 既有内容修改 | [对应单位/塔/水晶/地图](units/README.md)，再读受影响专题；从该内容定义与表现入口定位 | 受影响机制回归；模型/特效看实际渲染，声音实际试听 |
| 通用机制调整 | [状态落地现状](status/IMPLEMENTATION.md)、对应状态正文；部署读 [部署规则](UNIT_DEPLOYMENT.md)，移动碰撞读 [接触模型](BATTLE_CONTACT_MODEL.md) | 对应领域套件和跨卡边界，载荷变化补联网验证 |
| 工具开发 | [工具索引](../tools/README.md)、对应工具 README；工作台另读 [工作台](DEVELOPMENT_WORKBENCH.md) | Python/工具针对性检查及真实入口运行 |
| 其他工程任务 | 结构/性能读 [维护架构](MAINTENANCE_ARCHITECTURE.md)，联网另读 [协议契约](reference/NETWORK_PROTOCOL.md)；[测试手册](../tests/README.md) | 阶段针对性检查，最终必要整体回归；性能结论必须有测量 |

素材专题只读本次涉及的部分：卡面/图标读 [美术接入](ART_PIPELINE.md)；模型再读 [近战](MELEE_3D_INTEGRATION.md) 或 [远程](RANGED_3D_INTEGRATION.md)；建筑/特殊形态读对应单位动画页；地图读 [竞技场](units/arena.md)；声音读 [音频流程](AUDIO_INTEGRATION.md) 与对应音频页。仅文档改动核对相关实现及 [逐卡覆盖](reference/UNIT_DOC_COVERAGE.md)，执行文档审计，不把历史测试当成当次验证。

常用素材提取、模型摄影、动作预览和声音试听先查 [工具索引](../tools/README.md)，运行代码职责见 [scripts 导航](../scripts/README.md)。

默认路线只读当前资料。`docs/archive/`、历史交付不是常规必读；需要追溯或用户明确指定问题/改动记录时才定向读取。`docs/issues/` 仍可能有有效任务。

[导航声明](navigation.json) 记录审计所需当前入口、精简路线和卡牌形态文档例外；它不参与战斗运行。文档职责：本页选读、架构写所有者、状态正文写规则、IMPLEMENTATION 写支持能力、单位页写中文玩法、reference 写精确契约、tests 写验证。禁止以历史验收代替当前验证。

## 素材与迭代边界

运行资源目录 `assets/` 只保留已接入素材及必要依赖。开发内容统一使用项目根目录的 `ClashLegends-开发素材库/`：

| 分类 | 用途 |
| --- | --- |
| `01-待开发/<内容>/` | 已收集，尚未开始开发 |
| `02-候选讨论/<主题>/` | 正在挑选、等待决定的素材 |
| `03-制作中/<内容>/` | 已决定制作、仍在修改的当前版本；3D 地图在这里 |
| `04-中间产物/<内容或任务>/<批次>/` | 跨卡研究、转换试样、截图录音、构建与验证日志 |
| `05-已完成/<卡牌>/{源件,候选与来源,过程记录}/` | 已完成卡牌的可编辑源件、原始包、候选和制作历史；保留复用价值 |

同一内容随阶段迁移，不在各分类重复留副本。未完成的可编辑源工程保留在制作中，完成后进入已完成；正式接入时将最终资源及必要纹理/动画依赖同步到 `assets/`，核对引用与来源。外部共享原始库始终只读，不移动原包。不能将运行依赖误判为缓存。

候选查看优先复用 `python3 tools/dev.py model` 和 `audio`，用文件路径、清单和参数组织每次展示；缺能力时扩展通用工具，不为每次讨论重写展台。卡牌开发工作台只检查正式配置及实战表现，不加载候选清单。需要实战联调时用 `python3 tools/dev.py stage` 建立开发素材库内副本；`stage --arena --open` 复用现有地图预览。试接入完成并验证后再将最终改动同步正式工程，不把整个副本搬回。

失败或被替代的版本先区分独特源件、必要证据与可再生成产物；有复用价值的源件保留，确认废弃的产物可恢复删除，不整批换目录长期堆放。清理边界见 [工具索引](../tools/README.md#产物与清理)。不在 `assets/` 设置归档。宣传视频素材单独位于项目根目录的 `ClashLegends-promo-materials/`，不属于开发素材库。两个目录是本地工作区，已整体加入 `.gitignore`，并用 `.gdignore` 排除 Godot 导入；它们不会上传到 GitHub。制作源件、轻量候选与迁移的旧素材仍按分类保留在本机，正式运行依赖必须同步到 `assets/`，来源、迁移和验收结论保留在仓库文档中。历史改动记录中的素材库路径是本地验证产物路径，不代表仓库内有对应文件。

回血、移动减速、眩晕、减攻速的受影响对象提示统一复用通用特效，新增卡牌不得自建一套；入口及施法范围提示边界见[统一接入约定](status/PRESENTATION.md#统一接入约定)。

本机素材索引、旧路径兼容和可逆迁移见[素材归档索引](reference/MATERIAL_LIBRARY.md)。

## 文档与记录

- 可复用文档模板统一放在 `docs/templates/`：单位文档用 [卡牌模板](templates/card.md)，任务改动记录用 [改动记录模板](templates/change_record.md)。填写后的文档分别放在 `docs/units/` 和 `docs/deliveries/`，后续新增模板也遵循此约定。

- 需要需求文档的新卡可按类型使用 [单位卡模板](templates/unit_card_requirement.md)、[建筑卡模板](templates/building_card_requirement.md) 或 [法术卡模板](templates/spell_card_requirement.md)，填写后放项目根目录 `需求文档/`。未填数值由 agent 参考现有体系补齐，其他留空内容按设计意图和现有流程决定，开发过程中需要澄清时可以询问用户；明确写“无”的内容不添加，已指定要求不得擅自更改。素材与验收沿用当前开发流程，不因留空跳过。

- 单位手册面向不阅读代码的用户：总览直接列中文数值与规则，链接动画、音频和适用特效页，均能返回总索引。
- 蓝红版本合篇；独立形态分篇；冰鸟与蛋、大小纳尔、墓碑与雾行者双向链接。不得自动覆盖为字段或源码清单。
- 来源迁移与加工参数放素材记录；详细验收和已结束讨论放归档。缺素材、缺入口和未验收要分清。
- 核心回归、联网、美术目视、音频试听按 [测试手册](../tests/README.md) 和受影响范围执行。只接某个阶段就完成该阶段；完整新卡不能漏掉音频。

## 改动记录

只有实际修改项目（代码、配置、资源、工具及正式文档）才记录。讨论、问答、解释和只读检查不写记录。

同一任务周期只维护一份 [改动记录](deliveries/README.md)：初版实现后，测试反馈与后续修正继续按日期追加，不每轮新建。新卡制作各环节与反复调整属于同一周期；独立新任务另建记录，不使用永久增长的总日志。继续任务时先找该任务已有记录，无需通读其他历史。

文件开头简短维护当前结果和遗留项，后面按日期追加实际改动、必要原因、验证结果和未验证项。使用 [模板](templates/change_record.md) 起稿，文件名沿用任务开始日期。不要重复整段需求、抄聊天过程，或把未实施讨论写成完成事实。最终回复链接到这份记录。

当前设计文档说明现在怎样运行，改动记录说明本次改了什么；实现变化直接更新当前正文。历史记录退出默认阅读路线，合并或删除前保留有价值的决策依据。有问题文档时关联 [问题档案](issues/README.md)，没有则直接依据对话。

- 工作台仅作预览与操作实验，不添加验收勾选、验收持久化或报告导出；验证结果写在该任务的改动记录中，不要求用户在工作台标注。
